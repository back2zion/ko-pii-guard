`robustness.jsonl` is a manually curated **synthetic development regression set**.
It covers Korean labels adjacent to numbers, numeric token boundaries, misleading
context, collisions with existing identifier types, and Unicode formatting.
The annotations specify the expected entity and original Python string offsets
(`start` inclusive, `end` exclusive). Expected labels were assigned to the
constructed examples, not copied from model predictions.

These examples are also used in the test suite. Results therefore measure
regression behavior on known cases, **not held-out accuracy or real-world
precision**. The numbers are test examples with no verified ownership; they are
not guaranteed to be unassigned. Account examples do not validate bank ownership,
account existence, or a complete list of bank formats.

Run `uv run python benchmarks/robustness_benchmark.py --output /tmp/robustness.json`.
The report includes exact entity-and-span precision, recall and F1, false-positive
sentence counts, and the proportion of expected spans fully replaced by stars
in the actual masking output. It also records every error and the corpus SHA-256
so reported measurements can be tied to the exact input data.

`name_field_boundaries.jsonl` is a synthetic development regression set for
explicit person fields: 16 structured positive and 7 negative cases, plus one
separate prose positive. Gold name strings and
their original offsets were assigned before running the detector. It covers
middle dots in Korean/Latin/Cyrillic names, combining accents, fullwidth letters,
quoted fields, following fields, and tab/multiple-space honorific separators.
It also includes ordinary-name controls and non-person field/instruction cases.
These are constructed examples, not verified identities or independent samples.

The dataset was measured before changing the field recognizer, then reused to
validate that change. It is development data, **not a new held-out evaluation**
of contextual NER. The frozen `name_context.jsonl` and its original reports were
not changed. Reproduce the field check with:

```bash
uv run --frozen python benchmarks/name_address_benchmark.py --data benchmarks/data/name_field_boundaries.jsonl --check --check-negatives
```

Annotation correction (2026-10-10): the original field corpus marked
`안나·가온 씨가 방문했다.` negative to express the rules-only profile's scope.
That was an incorrect semantic annotation: it is a positive name in prose. The
current corpus assigns its actual gold span with `track="prose"`; `--check`
continues to gate only the 23 structured cases (16 names, 7 negatives).
`name_field_boundaries_v1.jsonl` preserves the original 24-case file and its hash
for the historical before/after reports. Those v1 negative counts include this
incorrect annotation and must not be used to evaluate contextual NER. The v2
context-head regression report uses the corrected current file and records its
new hash. No existing model prediction was used as a gold name boundary.

`name_context_training.jsonl` is generated by
`benchmarks/name_context_training_cases.py`, before model inference. It contains
1,758 training, 80 validation and 140 evaluation sentences, with disjoint target
names, full sentences and context IDs between splits. The 808 old name-context
cases are included in TRAINING, since their model errors were already inspected.
Validation selects the checkpoint; evaluation is run after selection. The new
evaluation has 128 synthetic names and 12 negative sentences across crossed
templates. It is limited engineering evidence, not a representative real-world
corpus. The directly authored generator and synthetic annotations are covered by
this repository's Apache-2.0 license; name combinations are not guaranteed to be
unassigned real identities. See the checkpoint model card for measured results
and remaining regressions.

`name_context_v2.jsonl` is generated by `name_context_v2_cases.py`. It preserves
all inspected v1 splits and existing development annotations as TRAINING data,
adding one-character, multiple-person, filename and ordinary-word contrast
examples. The v2 splits contain 4,488/168/232 train/validation/evaluation
sentences. All gold name strings (including secondary and repeated people),
sentences and context IDs are disjoint across those splits. Known regressions
also participate in explicitly declared checkpoint selection; their success is
development evidence. The separately named 232-case evaluation contains 300 gold
names and 32 negatives and is run after selection. Its crossed templates do not
represent independent field samples. The generator, original v1 files, frozen
manifests and both checkpoint versions are retained. See
`docs/name-context-v2-evaluation.md` for results and remaining new errors.

`name_context_v3.jsonl` is generated by `name_context_v3_cases.py`. All inspected
v2 splits are copied verbatim into TRAINING, with additional positive/negative
contexts addressing the previously observed failures. There are 6,520 training,
84 validation and 280 new evaluation sentences. All gold name strings, literal
sentences and context IDs are disjoint across splits. The new evaluation was
frozen before training and is used only after checkpoint selection. It contains
crossed synthetic templates, not representative field samples.
`name_context_v2_regressions.jsonl` is an exact preserved copy of the 232 retired
v2 evaluation rows, explicitly used as DEVELOPMENT selection data. Its 26 error
sentences are named Red/Green tests; 24 missed spans and five erroneous predicted
spans must not be confused with 29 distinct sentences. Original files remain
unchanged. See `docs/name-context-v3-evaluation.md` and the v3 training manifest.

`name_context_v4.jsonl` is generated by `name_context_v4_cases.py`. All inspected
v3 splits are copied into training with unchanged text and gold annotations.
Additional non-person contexts cover slogans, common-noun explanations and
vocabulary files; positive and mixed title/author contexts retain genuine names.
There are 8,038/68/222 training/validation/evaluation sentences. The new 222-case
evaluation contains 270 gold names and 60 non-person sentences. All gold name
strings, sentences and context IDs are disjoint across the splits. It is frozen
before fine-tuning and evaluated after checkpoint selection; it is synthetic
engineering evidence, not a real-world accuracy estimate.
`name_context_v3_regressions.jsonl` preserves the 280 retired v3 evaluation rows
as explicit DEVELOPMENT selection data. Original v3 files and results remain
untouched. See `docs/name-context-v4-evaluation.md` for Red/Green checks and results.


## v6 비인물 판정과 회귀 방지

`name_context_v5.jsonl`까지 확인한 자료는 모두 v6 개발 자료로 전환했다.
`name_context_v6_cases.py`가 `name_context_v6.jsonl`을 재현한다. 학습 8,616 /
검증 96 / 평가 192문장으로, 이름·원문·문맥 ID가 분할 간 겹치지 않는다.
평가에는 이름 234개와 비인물 48문장이 있다. 첫 v6 학습은 개발 오탐 1건이 남아
평가 전에 탈락했다. 재학습에서 개발·검증 조건을 충족한 epoch 139를 먼저 선택한 뒤
새 평가를 실행했다. 기존 정답 구간 225개를 모두 보존하고 비인물 오탐 8→0을
확인했다. 기존 미탐 9개는 남는다. [선택·탈락 기록](../../docs/name-context-v6-evaluation.md).
이 평가로 후속 수정을 한다면 개발 자료로 재분류하고 새 평가를 만들어야 한다.


## v7: 기존 미탐 9건 수정

v6의 평가 192문장을 `name_context_v6_regressions.jsonl`로 그대로 보존하고 전체
v6 자료를 v7 개발 학습 자료로 전환했다. 기존 평가를 다시 독립 평가로 제시하지 않는다.
`name_context_v7_cases.py`가 v7 데이터를 재현한다: 학습 8,904 / 검증 96 / 평가
192문장. 새 분할의 이름·원문·문맥 ID는 서로 겹치지 않으며 기존 원문·주석을 보존한다.
별도 평가에는 이름 234개·비인물 48문장이 있다. 30 epochs를 미리 정했고 개발
회귀 TP234/FP0/FN0 조건 충족 후 검증 점수로 epoch 25를 선택해 첫 평가를 실행했다.
기존 정답 224개를 보존하며 새 오탐 없이 TP/FP/FN 224/4/10→228/4/6을 확인했다.
수정한 기존 9건과 새 자료의 잔여 미탐 6건을 구분한다.
[상세 평가](../../docs/name-context-v7-evaluation.md).


## v8/v9: 미탐 6건·오탐 4건과 판정기 망각 수정

`name_context_v7_regressions.jsonl`은 원래 v7 평가 192문장을 그대로 보존한다.
v8 데이터: 학습 9,192 / 검증 96 / 평가 192문장. v8은 기존 10건을 모두
해결했지만 새 평가에서 기존 정답 1개를 잃어 탈락했다. 해당 평가 전체를
`name_context_v8_regressions.jsonl`로 보존하고 이후 개발로 전환한다.

v9 데이터: 개발(`train`) 9,480 / 검증 96 / 평가 192문장. v8 전체를 개발로
전환하며, 이름·원문·문맥 ID가 분할 간 겹치지 않고 기존 주석을 보존한다.
v9는 추가 학습이나 새 검증 분할로 선택하지 않고 고정 v7/v8 부모 가중치를 조합한다.
v7 보조 판정기를 교체하지 않고 개선 판정기를 추가해 회귀를 방지한다.

원래 v6/v7 평가 384문장에서는 TP468/FP0/FN0이며, v8 개발의 기존 정답
229개 보존·새 오탐 0개를 확인한 뒤 v9 새 평가를 실행했다. 새 평가 192문장은
이름 234개·비인물 48문장으로 TP/FP/FN 228/3/6→229/2/5이며 기존 정답
228개 손실·새 오탐 모두 0개다. [선택·탈락·재현 기록](../../docs/name-context-v9-evaluation.md).
새 자료의 다른 오류 5개 FN·2개 FP는 남는다. 이후 수정에 사용하면 다시 개발로
전환하고 독립 평가를 따로 만든다.

## v10/v11: 미탐 5건·오탐 2건과 필터 회귀 수정

`name_context_v9_regressions.jsonl`은 기존 v9 평가 192문장 원문이다.
6개 재현 테스트로 미탐 5개·오탐 2개를 고정했다. v10 데이터는 학습 9,768 /
검증 96 / 평가 192문장이다. v10은 기존 오류와 전체 1,389개 테스트를 통과해도
새 평가에서 기존 이름 ‘공감’을 잃어 탈락했다. 새 평가 원문은
`name_context_v10_regressions.jsonl`로 보존하고 v10 전체 자료를 개발로 전환했다.

v11 데이터는 개발 10,056 / 검증 96 / 평가 192문장이다. 이전 전체 주석을
그대로 유지하며 분할 간 이름·문장·문맥 ID가 겹치지 않는다. 생성기와 데이터 검사가
동결된 결과를 재현한다. v11은 기존 5/2건을 모두 해결했고 원래 v9 평가는
TP234/FP0/FN0이다. 과거 3,049문장의 기준 정답 3,222개 손실·새 오탐은 모두 0개다.
별도의 새 v11 평가에서는 TP/FP/FN 211/19/23→211/17/23, 기존 정답 211개 보존과
새 오탐 0개를 확인했다. 새 자료의 미탐 23개·오탐 17개는 남는다.
[선택·탈락·재현·한계](../../docs/name-context-v11-evaluation.md).
