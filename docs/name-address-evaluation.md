# 이름·주소 평가 데이터와 판정 범위

이름·주소는 **개발 중인 opt-in 기능**이다. 여기서 정의한 작은 세트는 회귀 진단에 사용하며,
README나 대외 소개의 정확도 표에는 쓰지 않는다. 모델 변경 전에는 별도로 동결한
[문맥 대조 세트](name-context-evaluation.md)를 먼저 측정한다.

[`benchmarks/data/name_address.jsonl`](../benchmarks/data/name_address.jsonl)은
직접 만든 한국어 **합성 개발 회귀 데이터**다. 개인정보가 포함된 실제 문서나
개인 주소록을 가져오지 않았다. 이름은 예시로 조합했으며 도로·동네·건물 이름은
`가상누리로`, `가상동`, `테스트아파트` 등을 사용했다. 예시 이름이 실제 사람의
이름과 우연히 같을 수 있으므로, 실존 인물의 기록이나 미사용이 보장된 값이라는
의미는 아니다. 주소의 실제 존재 여부도 이 데이터의 검증 대상이 아니다.

## 두 트랙

| `track` | 평가 대상 | 용도 |
|---|---|---|
| `structured` | 명시적 이름 필드, 완성된 도로명·지번 주소, 비슷하게 생긴 음성 사례 | 이름·주소 opt-in 규칙 인식기의 회귀 검증 |
| `free_prose` | 문장 속 이름·조사·동형이의어, 서술형 주소와 상세주소, 지역명·회사명·일반명사 | 선택적인 로컬 NER 모델과 문맥 판정의 도전 사례 |

`structured`의 이름 사례는 `성명`, `이름`, `예금주`, `수취인` 같은 필드의
값을 대상으로 한다. 이름 길이나 흔한 성씨만으로 정답을 정하지 않는다.
`이상`, `소망`, `오지은`, `남궁민수`, 드문 성씨, 한글 음역, 라틴 문자 이름을
포함한다. `회사명`, `상품명`, 빈 필드와 `미기재` 등은 음성 사례다.

`free_prose`에는 `오지은은`의 첫 번째 `은`은 이름에 속하고 두 번째 `은`은
조사라는 경계 문제, `신입 이상은`과 `더 이상`처럼 표면형이 같은 대조 사례를
넣었다. 이 트랙의 정답은 실제로 실행한 모델의 출력과 무관하게 문장 의도로
작성했다. 선택 모델이 모든 사례를 맞힐 것으로 가정하거나, 모델이 놓친 사례를
정답에서 지우지 않는다. 구조화 트랙과 자유 문장 트랙의 점수는 각각 보고한다.

두 트랙 모두 구현과 검증에 공개적으로 사용하는 개발 데이터다. 별도의
실사용 문서·도메인·작성자를 분리한 외부 평가 없이, 여기서 얻은 수치를
실서비스 정확도나 독립 평가 성능으로 표현하면 안 된다.

## 정답 구간

각 줄에는 `id`, `track`, `category`, `text`, `expected`가 있다.
`expected`의 각 항목은 `entity`, `start`, `end`를 가지며, 구간은 원문
Python 문자열의 시작 포함·끝 제외 인덱스다. 바이트 위치가 아니다.
이름 구간의 API 의미는 [KR_NAME 구간 계약](name-span-contract.md)을 따른다.

- 이름 엔티티는 `KR_NAME`이다. 성과 이름 전체를 포함하고 필드 라벨,
  공백 구분자, 뒤따르는 조사·`님` 등의 호칭은 제외한다. 이름 자체가
  `은`, `이`, `하나` 등으로 끝나더라도 이름의 글자를 삭제하지 않는다.
- 주소 엔티티는 `KR_ADDRESS`이다. 입력에 있는 시도·시군구·읍면,
  도로명과 건물번호 또는 동리와 지번, 이어지는 동·층·호를 포함한다.
  상세주소를 연결하는 주소 내부 공백·쉼표도 구간 안에 포함한다.
  배송 요청 같은 후속 문장과 문장부호는 제외한다.
- 주소 정책상 도시·구·역 이름만 있는 문장은 주소 양성으로 보지 않는다.
  `서울에서 만나요`, `강남구`, `강남역`은 음성이다. 이는 주소를 충분히
  특정하는 구간을 평가하기 위한 정책이며 일반적인 지명 NER의 정답과 다르다.
- 개인정보가 여러 개 있으면 각각 별도 구간을 기록한다. 두 이름을 한 구간으로
  합치거나, 이름과 주소 사이의 필드 라벨까지 덮는 결과는 exact-span 오류다.

괄호 안 동·건물명이나 줄바꿈으로 이어지는 주소는 자유 문장 도전 사례에도
포함한다. 규칙 인식기가 일부만 탐지하더라도 정답을 짧게 바꾸지 않는다.
도로명주소의 공식 구성은 행정안전부
[도로명주소 한글 데이터 설명](https://www.data.go.kr/data/15050417/fileData.do)을
참고했다. 이 합성 데이터는 해당 주소 원천을 복사하거나 전수 검증한 자료가 아니다.

## 결과 해석

트랙과 엔티티별로 **타입과 구간이 모두 같은** precision·recall·F1을 계산한다.
음성 문장 수와 오탐 문장 수도 분모와 함께 기록한다. 부분 탐지라도 원문 일부가
외부로 남을 수 있으므로, 실제 `stars` 마스킹 결과에서 정답 전체 구간이
가려졌는지를 별도 집계한다. 타입을 틀리게 붙였으나 전체를 가린 경우와,
타입은 맞았으나 민감 구간 일부를 놓친 경우를 구분할 수 있다.

모델 결과에는 모델 저장소와 고정 revision, 추론 설정, 데이터 SHA-256,
실행 명령을 남긴다. 이름·주소 opt-in 규칙의 측정과 선택 모델의 측정을 합쳐 하나의
대표 성능처럼 보고하지 않는다. 이 문서는 평가 조건만 정의하며 실행하지
않은 모델의 성능 수치를 제시하지 않는다.

## 파일명 판정과 프로필

기본 `DEFAULT_ENTITIES`는 기존 식별번호 9종을 유지한다. 이름·주소를 측정하는 이
벤치마크는 `SUPPORTED_ENTITIES`를 명시적으로 지정하며, 로컬 모델 유무를 구분한다.
NER 기본 임계값은 0.9, 규칙 임계값은 0.4다. 업무 문장 회귀에서 0.8의 이름 모델이
`새해`를 인명으로 판단하는 사례가 있어 더 보수적인 임계값을 선택했다. 이는 개발 세트에서
선택한 작동점이며 확률 보정이나 독립적인 최적 임계값 검증을 의미하지 않는다.

파일명이라는 이유로 이름을 제외하지 않는다. `김철수_이력서.pdf`와 이름이 포함된
이력서 경로를 양성 사례로 추가했다. `파일명: 이상`, `오지은이라는 파일을 열었다`는
당초 음성으로 작성했으나, 실제 인물 참조 여부를 확정할 근거가 부족하다는 검토에 따라
[별도 비채점 자료](../benchmarks/data/ambiguous_name_context.jsonl)로 옮겼다. 이 두 사례를
정상 탐지나 오탐으로 단정하지 않고 보고서의 `ambiguous_cases`에 예측을 공개한다.
모델 출력을 정답으로 바꾼 것이 아니라 판정 정책의 모호성을 공개한 것이며, 변경 전
데이터의 수치와 현재 보고서를 동일 분모로 직접 비교해서는 안 된다.

파일명·경로를 보존할 필요가 있으면 호출자가 알고 있는 구간을 기준으로
`mask(..., should_mask=...)`에서 치환 여부를 정한다. 이 선택은 `analyze`의 탐지 결과를
지우지 않으며, 콜백이 False를 반환한 개인정보는 원문에 남는다.

`이상은`의 끝 `은`처럼 조사와 같은 글자도 이름에 속할 수 있으므로 일괄적인 조사 제거는
구현하지 않는다. 모델 자체의 부분 탐지는 여전히 가능하다. 다른 모델로 바꾸거나 임계값을
조정할 때는 exact-span 지표와 전체 이름 마스킹을 모두 다시 측정해야 한다.
