# 이름 문맥 대조 평가

**후속 상태, 2026-10-10:** 아래 보고서는 당시 고정 E5 기준선과 사전 점수 비교의
역사적 기록이다. 이후 [문자 단위 이름 판정기](../artifacts/name-context-v1/README.md)
실험에서 이 808문장을 학습 자료로 사용했다. 따라서 새 판정기에 대해 이 자료의 점수를
독립 평가로 인용하지 않는다. 새 이름·문장 틀을 분리한 평가 결과와 남은 회귀는 해당
체크포인트 문서를 따른다. [최근 연구 검토](name-context-research.md)도 함께 남겼다.

이름 탐지는 **개발 중인 opt-in 기능**이다. 이 평가는 재학습 전에 현재 모델의 한계와
사전 점수 가산의 영향을 확인하기 위한 합성 진단이다. SoftLexicon을 구현하거나 NRB의
원래 데이터·훈련 방법을 재현한 것이 아니다. 정확한 서지와 적용 범위는
[참고 문헌](name-address-sources.md#핵심-참고-문헌)에 있다.

## 평가를 먼저 고정하기

1. [구간 계약](name-span-contract.md)에 따라 사람이 정한 문장 의도와 이름 본체를 주석한다.
2. 모델 출력을 보지 않고 문장·분할·사전·비교 설정을 확정한다. 생성기와 JSONL을 검사하고
   해시를 고정한 뒤 추론한다. 틀린 모델 출력에 맞춰 정답을 고치지 않는다.
3. 고정 공개 모델의 현재 동작과 사전 점수만 바꾼 실험을 같은 원시 후보에서 비교한다.
4. 남은 문맥·경계 오류를 보고 후속 학습의 필요성을 판단한다. 이 자료를 본 뒤 조정한
   새 모델은 별도의 새 평가 자료에서 확인해야 한다.

[`name_context_cases.py`](../benchmarks/name_context_cases.py)는 모델을 불러오지 않고
[`name_context.jsonl`](../benchmarks/data/name_context.jsonl)을 생성한다. 표면형은 일반적인
이름 조합, 낯선 성씨 형태를 조합한 이름, 일반명사와 같은 이름으로 나눈다. 이 구분은
설계 목적이지 이름의 실제 빈도 조사나 희귀도 보증이 아니다. 기존 모델의 사전학습에서
본 이름인지도 알 수 없다.

| 분할 | 문장 | 양성 / 음성 문장 | 대상 이름 수 | 문맥 ID 수 | 용도 |
|---|---:|---:|---:|---:|---|
| `calibration` | 132 | 96 / 36 | 12 | 44 | 점수 실험의 이름 사전 구성 |
| `challenge` | 448 | 348 / 100 | 20 | 123 | calibration과 대상 이름·문장 틀을 분리 |
| `seen_surface_challenge` | 228 | 192 / 36 | 12 | 52 | 사전에 있는 이름을 새 문장 틀에서 평가 |

위 표는 **자료 구성**이다. 총 808문장·32개 대상 표면형·203개 문맥 ID이며 양성 문장마다
이름 정답이 하나 있다. 양성 문장은 24개 인물 문장 틀과 7개 경계 문장 틀에 이름을 교차
대입했다. 172개 음성 문장은 일반명사 용법으로 작성했다. 따라서 808개의 독립 표본으로
해석하거나 일반적인 오탐률의 신뢰구간을 계산하지 않는다. 문맥 ID가 다르다는 것도
도메인·작성자·의미가 통계적으로 독립적이라는 증거는 아니다.

`seen_surface_challenge`는 calibration의 이름을 재사용하고 challenge의 인물 문장 틀을
재사용하므로 두 자료와 의도적으로 겹친다. 별도로 보고하며 점수를 합쳐 평가 표본을
부풀리지 않는다. 분할 간 대상 이름이 달라도 배경 단어까지 모두 다른 것은 아니다.
예를 들어 challenge 음성 문장의 일반명사 `하나`가 calibration 사전에 있을 수 있다.

일반명사와 같은 이름은 인물/비인물 문맥을 같은 `group_id`로 묶는다. 인물 문장 틀은
여러 이름군에 동일하게 적용하고 `context_id`별로 비교한다. `이상은의`·`이상의`·
`오지은은`·`김하나가`는 경계 트랙에서도 검사한다. 하나의 문장 틀에 맞춘 성능 개선과
여러 문맥에서 유지되는 개선을 구분하기 위한 구성이다.

## 고정한 점수 비교 조건

[`name_context_benchmark.py`](../benchmarks/name_context_benchmark.py)는 기존 E5 고정
revision `a308c54b4407819624a5661e31e162a269f39818`을 로컬 CPU에서 사용한다.
모델 가중치·토크나이저·라벨·후처리·엔티티 목록은 두 조건에서 동일하다.

| 조건 | 후보의 최종 NER 점수 | NER 임계값 | 전체 탐지기 임계값 |
|---|---|---:|---:|
| `baseline` | 기존 모델 점수 | 0.9 | 0.4 |
| `lexicon_score_only` | KR_NAME 후보 전체 문자열이 사전에 있으면 +0.05, 최대 1 | 0.9 | 0.4 |

사전은 calibration 양성에서 지정한 이름 12개뿐이다. challenge 정답으로 사전을 늘리지
않는다. 가산량 0.05는 추론 전에 고정한 단일 비교 조건이며, 최적값을 찾거나 확률을 보정한
결과가 아니다. 일반명사 `하나`·`사랑`·`미소`도 사전에 있으므로 오탐 승격 가능성을 검사한다.

원시 NER 후보는 임계값 0으로 한 번 받아 변경 불가능한 튜플로 저장한다. 각 조건은
같은 후보의 사본에 최종 임계값 0.9를 적용한다. 낮은 점수 후보를 확보하는 것 외에는
기준선 동작을 바꾸지 않는다. 점수를 더해도 새 구간을 만들거나 경계를 바꾸거나 라벨을
바꾸지 않는다. 부분 문자열 사전 매칭도 하지 않는다. 그 뒤에는 기존 필드 우선 규칙과
문맥 판정 등 실제 `KoreanPIIGuard` 경로를 그대로 거친다.

후보를 새로 만들지 않아도 임계값을 넘는 오탐이 생길 수 있다. 사전은 확정 판정이 아니라
점수 신호라는 원칙을 시험할 뿐이다. 이 코드는 **벤치마크 전용**이며 제품에 사전이나
점수 가산 옵션을 추가하지 않았다. SoftLexicon의 임베딩 결합이나 NRB의 적대적 학습을
구현하지 않았고 재학습도 하지 않았다.

## 집계 정의

- exact-span TP/FP/FN은 엔티티와 시작·끝이 모두 같은 경우를 정답으로 센다. 실제
  11종 opt-in 프로필을 사용하므로 이름 문장에 다른 유형이 잘못 나오면 그것도 FP다.
- `fully_masked_gold`는 실제 `mask(style="stars")` 출력이 정답 전체를 가렸는지 검사한다.
  이름을 일부만 가린 경우와 조사까지 과하게 가린 경우를 구분한다.
- `boundary_error_gold`는 같은 유형의 겹치는 예측이 있지만 정확한 구간이 없는 정답 수다.
  일부만 탐지, 과대 구간, 이름을 여러 조각으로 분리한 경우를 세부 집계한다. 세부 항목은
  서로 겹칠 수 있다. `missed_gold`는 같은 유형의 겹치는 예측 자체가 없는 경우다.
- 음성 오탐 문장 수뿐 아니라 실제로 바뀐 음성 문자 수도 센다. 마스킹 문자 수는 원문
  좌표의 합집합이며, 겹친 예측을 중복 계산하지 않는다. 원래 별표였던 문자는 변경에 포함하지 않는다.
- 표면형 대조 그룹은 인물·비인물 문장을 **모두** 맞혀야 통과다. 인물 문장 틀도 그 틀에
  넣은 모든 이름의 정답을 맞혀야 통과다. 이 엄격한 집계는 문장별 점수와 별도로 보고한다.
- 사전 적중 후보, 임계값 직전 후보, 승격 후보의 원래/변경 점수, 최종 TP·FP 변화와
  좋아진/나빠진 문장 ID를 남긴다. 사전에 없는 이름에서 보정 대상이 없다면 효과가 검증된
  것이 아니라 사전의 적용 범위가 제한된 결과다.

## 실행과 결과 파일

```bash
uv sync --frozen --extra dev --extra guardrails --extra ner
uv run --frozen python -m ko_pii_guard.ner --download
uv run --frozen python benchmarks/name_context_cases.py --check
uv run --frozen python benchmarks/name_context_benchmark.py --output benchmarks/results/name-context-e5.json
```

다운로드는 설치 시 명시적으로 실행하며 평가 추론은 로컬 캐시만 사용한다. JSON 보고서에는
데이터·생성기·평가기·라이브러리 소스 해시, 모델 revision, 임계값, 의존성 버전과 오류 ID가
들어간다. 같은 이름의 `.predictions.jsonl`에는 사례별 원시 모델 후보와 두 조건의 최종
탐지·마스킹 집계가 있다. 원시 후보 위치는 정규화 문자열 기준, 최종 예측 위치는 원문 기준이다.
평가 중 입력 해시가 바뀌면 보고서를 만들지 않는다.

## 2026-10-10 실행 결과: 기술 진단

Python 3.12.13, CPU 2 threads, 위 고정 E5 모델과 기존 11종 선택 프로필로 실행했다.
기본 9종 식별번호의 벤치마크와 합산하지 않는다. 이 표의 분모는 위 합성 곱집합의
문장·구간 수이며 독립 실사용 표본 수가 아니다. README 정확도 표에는 싣지 않는다.

**점수 가산 없는 기준선, 각 양성 문장에 KR_NAME 정답 하나:**

| 분할 | 정확한 구간 TP / FP / FN | Precision / Recall / F1 | 전체 마스킹 | 음성 오탐 문장 | 잘못 가린 음성 문자 |
|---|---|---|---|---|---|
| calibration | 72 / 1 / 24 | 98.63% / 75.00% / 85.21% | 73/96 | 0/36 | 0/656 |
| challenge | 298 / 2 / 50 | 99.33% / 85.63% / 91.98% | 299/348 | 1/100 | 2/2,197 |
| seen_surface_challenge | 147 / 5 / 45 | 96.71% / 76.56% / 85.47% | 149/192 | 1/36 | 4/868 |

FP에는 음성 문장의 오탐뿐 아니라 양성 문장에서 경계가 잘못된 예측도 포함된다.
예를 들어 이름과 조사까지 가린 예측은 exact-span FP와 FN이지만 전체 마스킹에는
성공할 수 있다. 그래서 전체 마스킹 분자가 정확한 TP보다 클 수 있다.

| 분할 | 사전 적중 원시 후보 | 0.9를 넘도록 승격된 후보 | 정확한 TP 변화 | FP 변화 | 좋아진 / 나빠진 문장 |
|---|---:|---:|---:|---:|---:|
| calibration | 78 | 1 | 72→73 | 1→1 | 1 / 0 |
| challenge | 0 | 0 | 298→298 | 2→2 | 0 / 0 |
| seen_surface_challenge | 155 | 1 | 147→148 | 5→5 | 1 / 0 |

승격된 두 후보는 신청서 문장의 `견다온`(약 0.8594→0.9094)과 새 봉사자 문맥의
`미소`(약 0.8707→0.9207)였다. 전자는 사전 구성에 사용한 calibration 결과이며,
후자는 같은 표면형의 새 문맥 결과다. 둘 모두 정확한 구간으로 탐지·마스킹됐다.
두 조건에서 음성 오탐과 경계 오류는 동일했다. challenge의 사전 적중 0건은 보정의
안전성이나 일반화 성공 증거가 아니라 적용할 후보가 없었다는 뜻이다.

표면형별 인물·비인물 문장을 전부 맞힌 대조 그룹은 두 조건 모두 calibration **0/3**,
challenge **0/4**, seen_surface_challenge **0/3**이었다. 인물 문장 틀의 모든 이름을
맞힌 틀도 각각 **2/8, 2/16, 1/16**으로 변하지 않았다. 이는 엄격한 그룹 진단이며,
모든 문장이 틀렸다는 뜻이나 일반화된 오탐률이 아니다.

challenge의 이름군별 정확한 TP/정답은 일반적인 합성 이름 **149/149**, 낯선 성씨 조합
**107/128**, 일반명사 동형 이름 **42/71**이었다. 마지막 그룹에는 경계 트랙의 `이상`
7문장도 포함한다. 특정 이름군과 작성한 문장 틀에 한정된 결과이며 실제 이름 빈도에 따른
성능 추정이 아니다. 작은 전체 평균이 가릴 수 있는 문맥 의존의 차이를 드러낸다.

실제로 남은 오류는 다음과 같다. 모델 점수는 반올림했으며 오류 문장도 원래 분모에 남겼다.

| 분할 / 문장 | 정답 | 기준선 예측 | 오류 |
|---|---|---|---|
| challenge: 새해의 소망은 가족 모두의 건강이다. | 이름 없음 | `새해` (0.9939) | 일반 문장 오탐 |
| seen: 조각상의 미소는 보는 방향에 따라 달라 보였다. | 이름 없음 | `조각상의` (0.9992) | 일반 문장 오탐 |
| seen: 간호사는 대기 중인 환자 사공이든 씨를 진료실로 안내했다. | `사공이든` | `든` (0.9945) | 이름 앞부분 노출 |
| challenge: 현장을 목격한 이상이 담당 조사관과 만났다. | `이상` | `이상이` (0.9758) | 조사까지 마스킹 |

세 분할의 경계 오류 정답 수는 **1, 1, 4**였고, 마지막 분할의 4건은 부분 탐지 2건과
과대 구간 2건이었다. `사공이든`의 다른 작업자 문맥에서도 `든`만 탐지했다. 오류 예시를
보고 금지어나 조사 제거 규칙을 추가하지 않았다. API 구간 계약의 통과와 실제 모델이
그 경계를 찾아내는 능력은 별개다.

### 이번 비교에서 내린 결정

점수 가산은 기존 후보 두 개만 살렸고 일반명사 오탐·부분 이름 탐지·대조 그룹 실패를
해결하지 못했다. **제품에는 적용하지 않는다.** 새 모델 재학습도 실행하지 않았다.
문맥과 경계를 개선할 후속 학습을 검토할 근거는 생겼지만, 이 실험만으로 재학습의 개선
효과나 SoftLexicon/NRB 중 어느 방식이 유리한지 알 수는 없다.

다음 실험은 동형어 인물/비인물 문맥과 이름 전체 경계를 대상으로 하되, 학습 자료의
권한·도메인·이름·문장 틀을 분리하고 새로 보류한 자료에서 검증해야 한다. 오탐 문장·
잘못 마스킹한 문자·전체 이름 노출을 우선 비교하고 재현율 상승만으로 채택하지 않는다.
현재 결과는 추가 학습 이후의 독립 평가 자료로 재사용하지 않는다.

원본 [JSON 보고서](../benchmarks/results/name-context-e5.json)와
[사례별 후보·최종 집계](../benchmarks/results/name-context-e5.predictions.jsonl)를 함께 보존했다.
