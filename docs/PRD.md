# ko-pii-guard 제품 요구사항

갱신일: 2026-10-10

## 목표

대한민국의 한국어 업무 텍스트에서 개인정보를 탐지하고 마스킹하는 신뢰할 수 있는
오픈소스 라이브러리를 만든다. 최고의 오픈소스를 지향하되, 우수성은 공개된 비교 평가와
재현 가능한 결과로 입증한다. 현재 최고 정확도를 달성했다고 주장하지 않는다.

## 사용자와 핵심 흐름

- 서비스 개발자: 로그·상담·문서의 텍스트를 외부 시스템으로 보내기 전에 마스킹한다.
- 데이터 담당자: 사람이 검토할 탐지 구간과 원문 좌표를 얻고 업무에 맞는 치환 정책을 적용한다.
- 한국어 AI 개발자: 기본 규칙 또는 선택적 로컬 NER를 재사용하고 Guardrails에 연결한다.

핵심 API는 `analyze`, `contains_pii`, `mask`다. 기본 설치는 모델 다운로드 없이 동작하고,
탐지 과정에서 원문을 외부 추론 서비스로 전송하지 않는다.

## 현재 구현 기준선

- 기본 9종: 주민번호, 외국인등록번호, 사업자번호, 운전면허번호, 여권번호,
  전화번호, 이메일, 카드번호, 계좌번호.
- 이름·주소는 실험적 선택 기능이다. 명시적 필드·주소 문법과 선택적 로컬 NER를 지원한다.
- 유니코드 표기 정규화 후에도 원문 Python 문자 좌표를 반환한다.
- 태그·별표·부분 마스킹과 호출자 선택 콜백을 지원한다.
- 저장소에는 PyPI 0.2.0 이후 미배포 변경이 있다. 구현 완료와 배포 완료를 구분한다.

지원 범위와 한계는 [개발 안내](development.md), 실행한 평가 결과는
[평가 문서](evaluation.md), 이름 문맥 평가는 [별도 문서](name-context-evaluation.md)를 따른다.

## 필수 품질 계약

1. 반환 구간은 원문에서 정확히 재현되어야 하며 서로 겹치지 않아야 한다.
2. 마스킹은 선택한 탐지 구간을 치환하고 나머지 문자를 보존해야 한다.
   부분 마스킹과 콜백이 남기는 정보는 API 문서에서 명시한다.
3. 이름의 본체·조사·파일명 경계는 [구간 계약](name-span-contract.md)을 따른다.
4. 모호한 주문번호·날짜·일반 명사로 인한 오탐과 개인정보 미탐을 함께 측정한다.
5. 타임아웃이나 잘못된 NER 결과는 예외로 전달한다. 성공처럼 원문을 반환하지 않는다.
   호출 서비스가 예외 시 외부 전송을 중단하도록 통합 예제를 제공한다.
6. 새 탐지 규칙에는 합성 양성·음성 사례, 충돌 사례, 원문 좌표·마스킹 검증을 포함한다.
7. 기준선이 맞힌 이름은 구간별로 보존한다. 오탐 감소가 기존 이름 미탐 증가를
   상쇄해서는 안 된다. 새 오탐 구간도 개별 비교하며, 조건 위반 모델은 채택하지 않는다.
   [회귀 방지 계약](name-context-nonregression.md)에 실패 사례와 검사를 연결한다.
8. 규칙 점수를 확률로 표현하지 않으며 작은 합성 회귀 결과를 실무 정확도로 일반화하지 않는다.

[선택적 문자 판정기 v1](../artifacts/name-context-v1/README.md)을 학습했다.
학습과 이름·문장 틀을 분리한 합성 평가 140문장에서 정확 구간은 91/128→107/128,
잘못된 예측 구간은 23→0, 전체 이름 마스킹은 98/128→107/128이었다.

다음 채택 조건은 별도 자료의 개선과 기존 동작 회귀 해소를 함께 확인하는 것이다.
기존 808문장 문맥 평가는 새 판정기에는 학습 자료로 재분류한다.

후속 v2에서 알려진 21개 미탐과 7개 회귀를 공개 API·실제 마스킹 검사로 해소했다.
한 글자 이름·파일명·다중 인물·동형어 양음성 문맥을 보강했고 v1 전체 자료는 개발 자료로
재분류했다. 새로 분리한 232문장에서는 v1의 정확 구간 196/300→v2의 276/300으로
개선됐지만 새 FN 24개·FP 5개가 남으므로 명시적 선택 기능을 유지한다.
[v2 평가와 남은 한계](name-context-v2-evaluation.md)에 개발 인수 검사와 새 평가를 구분해
기록했다. 다음 문맥 개선은 새 음성 오탐과 미탐을 대상으로 별도 자료에서 검증한다.

후속 v3에서 남은 오류가 발생한 26문장을 먼저 개별 회귀 테스트로 고정했다.
v2에서 26건 실패를 재현한 뒤 v3에서 모두 통과했고, 기존 v2 평가 전체는 공개 API
기준 TP/FP/FN = 300/0/0이었다. v2 전체 분할은 개발 학습 자료로 전환했다.
수정에 사용하지 않은 새 합성 평가 280문장에서는 400개 이름 중 395개를 정확히
찾았지만 FN 5개·FP 31개, 음성 문장 오탐 12/40이 남는다. 전체 999개 테스트가
통과해도 현장 무오류나 전 지표 개선을 뜻하지 않는다. 명시적 선택 기능을 유지하며
[v3 재현·평가 기록](name-context-v3-evaluation.md)에 개발 결과와 새 평가를 구분한다.

후속 비인물 수정은 이름 구간별 회귀 방지 조건을 적용했다. v4/v5 회귀 후보는
채택하지 않았으며 v6 선택 판정기의 새 합성 평가 192문장에서 기존 정답 구간
225개를 모두 보존하고 비인물 오탐 8/48→0/48을 확인했다. 기존 개발 회귀 자료의
비인물 오탐 12/40→0/40과 이전 정답 395개 보존도 확인했다. 새 자료의 기존 미탐 9개는
남는다. 전체 통합 테스트 1,354개 통과와 평가 한계는 [v6 기록](name-context-v6-evaluation.md)을

후속 v9에서 v7 미탐 6개·오탐 4개를 개별 테스트로 고정해 모두 해결했다.

새 자료의 다른 미탐 5개·오탐 2개는 남는다. [v9 검증·한계](name-context-v9-evaluation.md).

유지한다. v10은 새 평가에서 기존 이름 ‘공감’을 잃어 탈락시켰다. 회귀한 구간을
별도 테스트로 고정하고 해당 평가 전체를 개발로 전환했다. 기존 탐지기는 보존하고
필터 크기 확대·어려운 표본 재학습·강화된 이름 보존 기준을 적용한 v11은 전체
1,391개 테스트를 통과했다. 과거 3,049문장·정답 구간 3,222개 손실과 새 오탐은
모두 0개다. 새 평가 192문장에서는 기존 정답 211개 손실·새 오탐 0개,
TP/FP/FN 211/19/23→211/17/23이며, 별도 자료의 미탐 23개·오탐 17개는 남는다.
[개발·새 평가·탈락 기록·한계](name-context-v11-evaluation.md).

경우 해당 데이터를 개발 세트로 취급하고 별도의 평가 세트로 재검증한다.

## 자유 문장 알고리즘 연구 우선순위 (2026-10-10)

개별 실패 문장을 재학습하고 새 합성 틀에서 또 오류를 찾는 반복에서 전환한다.
v11의 이미 확인한 평가를 단계별로 다시 측정한 결과, 미탐 23건은 후보 없음 10건,
점수 탈락 10건, 겹침 병합 탈락 3건이다. 오탐 17건 중 13건은 정답과 겹치는 경계
불일치다. 이 재분석은 새 독립 평가가 아니며 새 모델의 개선 성과도 아니다.

P0 연구는 공동 문자 구간 채점·전역 구간 선택, 합법 BIOES 전이 비교,
문맥 대조 학습과 인코더 적응의 제거 실험이다. 새 보조 판정기 누적을 기본 해법으로
삼지 않는다. 출처·문서·작성 방식·분야가 분리되고 별도 검수된 평가와 calibration을
확보한다. 기존 정확 구간 보존뿐 아니라 실제 가림 범위의 노출 회귀도 차단한다.
단일 점수나 합성 회귀 통과로 자유 문장 오류 0을 선언하지 않는다.

[연구 근거·재현 진단·실험 설계·채택 기준](name-context-algorithm-research.md).
공동 문자 구간 채점과 전역 구간 선택의 첫 실험을 구현했다.
기존 진단 192문장에 실제 API·별표 마스킹을 실행하여 첫 후보의 미탐 23→2,
오탐 17→2를 확인했고 해당 자료에서 기존 정답·가림 보존과 새 오탐 차단을 통과했다.
세 번째 시드는 새 오탐 1개로 탈락했다. 이는 이미 확인한 합성 자료의 결과다.
[실험 프로토콜·외부 검증·채택 판정](name-span-experiment-v1.md)에 증거를 기록한다.
외부 KLUE 1,000문장의 정확 구간 F1은 기본 E5 85.05%, v11 73.75%,
새 후보 59.79~64.73%였다. 세 후보 모두 외부 회귀 게이트에서 탈락하여 채택을
거부했다. 다음 우선순위는 출처가 다른 개발 자료와 인코더 적응·문맥 대조의
제거 실험이다. 합성 진단 개선만으로 완료나 승격을 선언하지 않는다.
이번 변경은 연구용 구현이며 v11 가중치·기본 런타임은 교체하지 않았다.

실제 KLUE 학습 문장과 기존 합성 자료를 함께 사용하는
[문자 경계·인코더 적응 실험](name-generalization-v1.md)의 학습과 독립 평가를 완료했다.
정확 구간 F1이 높아도 실제 이름 전체 가림이 낮아지면 채택하지 않는다.
모든 개별 회귀는 평균과 별도로 기록하고, 모델 선택에 쓴 자료는 개발 자료로 명시한다.
새 KLUE 999문장에서는 F1 84.58%→89.14%, 오탐 138→99로 개선됐지만
기존에 가리던 이름의 새 노출 12개가 남았다. 출처가 다른 KDPII 500문장에서는
오탐 2→116, 비인물 오탐 문장 1→101로 악화되어 후보를 채택하지 않았다.
KLUE의 1,000개 고정 ID 중 학습 중복 1개는 추론 전에 제외했고 보충하지 않았다.
코드·기존 모델 통합 테스트 1,726개 통과와 이 모델의 채택 검사 실패는 구분한다.
다음 학습은 이름이 드문 대화 출처도 포함하고, 출처별 제약을 각각 적용해야 한다.
이미 확인한 평가 자료로 성능을 조정하면 해당 자료는 다음 독립 검증에 재사용하지 않는다.
[후속 v2](name-multisource-v2.md)는 구간 전체의 존재 근거와 문자 경계 판정을
구분하고, 개발 단계에서부터 모든 출처의 회귀 검사를 통과한 후보만 독립 평가한다.
고정 LoRA의 40개 정책은 모두 탈락했으며, 대화 자료를 포함한 별도 head의
재학습을 완료했다. 새 head의 초기 20개 개발 정책도 모두 탈락했다. 후속 비교는
불확실한 가림을 보존하고 구간 전체가 비인물인 사건에 강한 근거가 있을 때만
해제하는 방식이다. 추가·해제 각각의 대조를 포함한 20개 조합 중 한 정책이
개발·실추론 재생 검사를 통과했다. 새 탐지를 끈 정책이므로 미탐 개선은 없다.
텍스트 중복을 추론 전에 제외한 고정 KLUE 1,000 / KDPII 1,992문장의 새 평가를
시작했다. KDPII 한 문장의 동일 비인물 주석 반복은 원본 주석과 고유 이름 정답을
보존하는 별도 변환기로 처리했고, 기존 개발 500문장의 변환 동치를 검증했다.
새 KLUE 1,000문장에서는 오탐 138→137 대신 미탐 133→134, 기존 이름의 실제
새 노출 1개가 발생해 후보를 거부했다. 대화 추론은 작업 환경의 자원 부하 때문에
중단됐고 완료 점수를 산출하지 않았다. 필수 KLUE 검사가 이미 실패하여 추가
대화 추론을 재시작하지 않았다. 평가가 끝난 2,992문장으로 표시하지 않는다.
이름 전용 guard threshold 0.0의 검사이고 기본값 0.4의 성능을 뜻하지 않는다.
기본 E5의 사전학습 노출 여부는 별도로 확인하지 못했다. 일반 자유 문장의 미탐·오탐
문제는 여전히 미해결이며, 이번 후보를 기본 런타임으로 채택하지 않는다.

중단됐던 대화(KDPII) 추론은 이후 완료했다 (1,992문장, PS_NAME F1 85.71%,
PS_NAME+별명 F1 71.28%). 이 수치만 보고 처음에는 기존 E5 이상이라고 적었으나
**틀렸다.** `selective:addition=1.0:removal=0.9999` 정책의 실제 코드
(`scripts/name_selective_adapter.py`)는 `addition_threshold=1.0`이라 baseline이
못 찾은 이름을 추가하지 않고, `removal_threshold=0.9999` 이상으로 확실할 때만
baseline의 기존 구간을 제거하는 **보수적 오탐 제거 필터**다. 이 KDPII
1,992문장에서 baseline과 candidate의 F1은 **완전히 동일**했다 — 즉 이 구간에서
제거가 한 건도 일어나지 않았을 뿐, 어떤 개선도 없었다. WikiTree도 동일(418/418).
반면 NSMC에서는 이 필터가 기존 정답 구간 1개("가르시아", KLUE-NER 원본 골드가
이미 PS로 태깅한 외래 인명)를 잘못 제거해 회귀를 냈다. 즉 실제 순효과는
**이득 0 + 회귀 1건**이며, 처음 비교한 "0.13→0.86" 수치는 이미 거부한 다른
후보(`name-generalization-lora-v1`)의 것이었다. 자동 채택 게이트의 거부는
정확했고, 이를 사람이 override해서 배포하기로 한 앞선 결정은
[철회](name-multisource-v2.md#운영-배포-결정-게이트-통과가-아닌-사람의-승인-철회)했다.
이 후보는 기본 런타임으로 채택하지 않으며, 기존 E5 baseline을 그대로 유지한다.

## 범위 밖

실제 계좌 소유자·주소 실재 여부 확인, 건강보험 번호, OCR, 이미지·PDF 파싱,
가명처리의 재식별 위험 인증은 현재 제품의 완료 범위에 포함하지 않는다.
텍스트 마스킹 결과만으로 익명화나 법적 준수를 보장하지 않는다.

## 변경 관리

기능 변경 시 이 문서의 기준선·우선순위와 관련 API 문서를 함께 검토한다.
평가 수치는 실제 실행 결과와 데이터 해시·설정·명령을 연결하고, 배포 전에는
미배포 기능이라는 표시를 유지한다. PRD의 완료 조건은 구현·검증 증거로 확인한다.
