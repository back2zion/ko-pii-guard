## 1. 문제 정의와 이미 배제된 것

### 1.1 문제

한국어 자유 문장의 `KR_NAME`은 기본 E5(`FrameByFrame/korean-pii-e5-base`, revision
`a308c54b...`, 구간 임계값 0.9)에서 미탐·오탐·경계 오류가 모두 남아 있다. 기록된 기준선은 다음과 같다.
모두 이름 전용 `score_threshold=0.0` 조건이며 기본 guard 0.4의 성능이 아니다.

| 자료 (현재 상태는 3.1 참고) | 문장 / 이름 | E5 기록값 | 출처 문서 |
|---|---:|---|---|
| KLUE dev 1,000 (공동 구간 v1 외부) | 1,000 / 908 | TP 765, FP 126, FN 143, F1 85.05%, 이름 전체 가림 812 | span-experiment-v1, generalization-v1 |
| KLUE dev 999 (일반화 v1 새 KLUE) | 999 / 876 | F1 84.58%, FP 138, FN 133, 가림 실패 80 | generalization-v1 |
| KDPII test 500 | 500 / 18 (+별명 14) | F1 85.71% (이름), 61.22% (이름+별명) | generalization-v1 |
| multisource-v2 NSMC / Wikitree | 486 / 449, 514 / 418 | F1 80.58% / 88.44% | multisource-v2 |
| multisource-v2 KDPII | 1,992 | F1 85.71% (PS_NAME), 71.28% (+별명) | name-context-history |

원인에 대해 문서가 확인한 사실은 다음뿐이다.

- 합성 v11 진단 192문장의 미탐 23건은 정확 후보 없음 10, 점수 미달 10, 겹침 병합 탈락 3이다.
  후보 자체가 없는 10건은 필터·병합 조정만으로 복구할 수 없다. 오탐 17건 중 13건은 경계 불일치다.
  (이 분해는 합성 단일 창 자료이며 실제 문장 분해가 아니다.)
- 실제 KLUE 진단에서 정확 경계 미탐 143 중 이름 일부가 노출된 것은 96이고, 45개는 이름 끝이
  E5 토큰 내부에 있어 토큰 끝 출력으로 표현할 수 없었다(44개 조사 결합).
- 구간 오류와 전체 가림 실패는 다른 지표이므로 둘 다 보고한다.
- 원인(표현·전이 제약·학습 자료)의 기여도는 **아직 분리되지 않았다.** 각각을 제거 실험으로 구분해야 한다.

### 1.2 이미 배제된 후보와 사유

| 후보 | 결과 | 배제 사유 (문서 근거) |
|---|---|---|
| v4, v5(후보 판정기), v8, v10 | 새 평가에서 기존 정답 이름 손실 | 구간별 회귀 계약 위반. 보조 판정기 누적은 기본 해법이 아니다 (회귀 방지 계약, PRD) |
| v11 | 합성 192에서 TP 211, FP 17, FN 23. 외부 KLUE 1,000에서 F1 73.75% (E5 85.05%) | 기본 E5보다 낮아 승격 근거 없음 (span-experiment-v1) |
| 공동 구간 모델 v1 (3시드) | 합성 진단 FN 23→2~3이나 KLUE F1 59.79/64.73/63.79%, v11 대비 정확 구간 손실 176/162/161 | 합성 편중 학습이 외부로 일반화되지 않음. 전 후보 외부 게이트 탈락 |
| 일반화 v1 (LoRA, coverage 디코더, cutoff .01) | 새 KLUE F1 84.58→89.14%이나 기존 정확 구간 손실 10, 새 오탐 45, 이전 가림의 새 노출 12. KDPII 오탐 2→116, 비인물 오탐 문장 1→101 | 이름이 드문 대화 출처에서 낮은 문자 확률 cutoff가 보정 실패. 평균 개선이 개별 회귀를 상쇄하지 못함 |
| v2 구간 존재 판정 40개 + 재학습 20개 정책 | 모든 출처 조건을 통과한 정책 0 | 기존 가림 보호 시 새 오탐, 비보호 시 기존 이름 손실 |
| v2 선택 필터 `selective:addition=1.0:removal=0.9999` | KDPII·WikiTree는 기준선과 **완전 동일**(이득 0), NSMC에서 기존 정답 "가르시아" 제거(새 노출 1) | **이득 0 + 회귀 1.** 앞선 운영 배포 승인은 철회됨. 추가를 끈 필터이므로 미탐을 줄일 수 없는 구조 |

이 이력에서 얻는 설계 제약:

1. 제거 전용 필터는 미탐을 줄이지 못한다. 후보 생성 단계의 상한부터 올려야 한다.
2. 합성 자료만으로 학습한 구조 변경은 외부로 일반화되지 않았다(공동 구간 v1). 모든 P0 실험은 실제 문장과 대화를 처음부터 학습에 포함한다.
3. 낮은 cutoff는 이름이 드문 출처(KDPII)에서 오탐을 폭증시켰다. 출처별 오탐을 각각 게이트로 건다.
4. 합법 BIOES Viterbi는 일반화 v1 모델에 **이미 적용**되어 있었다. 따라서 P0-2는 새 아이디어가 아니라 통제된 제거 실험이다.
5. 거부 후보의 수치를 다른 후보의 근거로 쓰지 않는다(운영 승인 철회 사례). 모든 비교는 같은 실행에서 측정한 기준선과 한다.

## 2. 실험 계획 (우선순위 순)

### 2.0 공통 규약

**기준선 (P0-0, 먼저 수행).** 현재 기본 E5(임계값 0.9)를 후보와 같은 device·같은 라이브러리 버전에서
공개 `analyze`와 `mask(style="stars")`로 개발 자료 전체에 다시 측정해 동결한다.
v11은 외부에서 E5보다 낮았으므로 기준선이 아니라 참고값이다. 기준선 수치가 정해진 뒤
출처별 개선 목표를 정한다.

**공통 자료 (현재 상태 기준, 3.1과 동일).**

- 학습: KLUE NER v1.1 **train**의 Wikitree·NSMC(`prepare_name_generalization_data.py`),
  KDPII v1 **train**(`prepare_name_multisource_data.py`), 기존 합성 `name_context_v11.jsonl` train.
  입력 해시를 선택 전에 기록한다. 평가·개발 자료와 정확·정규화 텍스트 중복 0을 확인한다.
- 체크포인트 선택(검증): 위 자료의 해시 고정 검증분(KLUE 2,100, KDPII valid, 합성 96은 보고용).
  출처별 exact F1을 동일 가중치로 쓴 선택 규칙은 multisource-v2의 선택 방식을 재사용한다.
- 개발 비교(정책·cutoff·시드 비교, 반복 사용 허용): 3.1의 "개발 자료" 전체 — 이미 정답을 열었기 때문이다.
- 독립 최종 판정: **현재 사용 가능한 독립 heldout은 없다.** 새 자료(3장)가 준비될 때까지
  어떤 후보도 "독립 평가를 통과했다"고 보고하지 않는다.

**공통 지표 (문서에 이미 정의된 것만 사용).** 출처·정답 정책별 exact TP/FP/FN/F1,
실제 `mask(style="stars")` 기준 이름 전체 가림 수, 불필요하게 가린 문자 수, 비인물 문장 오탐 수,
개별 회귀 3종(기존 정확 구간 손실, 새 오탐 구간, 이전에 가려지던 이름의 새 노출),
문장 단위 paired bootstrap 500회 95% 구간(문서 단위가 아니므로 불확실성을 작게 추정할 수 있음을 명시),
시드 3개(20261010~20261012 또는 단계별 문서 시드). 추가 보고: 이름 유형·문서 길이별 최악 성능,
CPU 지연·메모리(PRD P1의 "처리시간"; 측정에는 `benchmarks/performance_benchmark.py`를
재사용하되 이름 후보에 맞는지는 **(가정)** 확인 필요).
KDPII는 `PS_NAME`과 `PS_NAME+PS_NICKNAME` 두 정책을 같은 예측으로 각각 보고하고 합산하지 않는다.

**출처별 회귀 제약 (모든 실험 공통, 개발 단계와 최종 단계 동일).** 출처 = NSMC, Wikitree,
KDPII `PS_NAME`, KDPII `PS_NAME+별명`, (있다면) 합성 회귀 자료. 각각에서 다음을 모두 요구한다.

- 기준선이 정확히 맞히던 구간 손실 0, 새 오탐 구간 0 (구간 단위 비교).
- 기준선이 전체 가리던 이름의 `stars` 마스킹 새 노출 0.
- 이름 전체 가림 수, 정확 F1이 기준선 이상. 비인물 오탐 문장 수, 불필요 마스킹 문자 수가 기준선 이하.
- 모든 변경을 끈 동치 대조는 개선 후보로 인정하지 않고, 어느 출처에서도 개선 지표가 하나도 없으면
  "이득 없음"으로 차단한다(multisource-v2 최종 검사 규칙).
- 평균 개선으로 개별 회귀를 상쇄하지 않는다. 과거 합성 회귀(3,222 정답·137 정답 문장 테스트)도
  `tests/test_name_context_nonregression_gate.py`, `test_name_context_no_recall_regression.py`,
  `test_name_context_role_regression.py`로 유지한다.

**채택 게이트 (모든 실험 공통).**
(a) 개발 자료의 모든 출처에서 위 제약 통과, (b) 3시드 모두 통과 **(가정: 공동 구간 v1에서 한 시드가
새 오탐 1개로 탈락한 전례에 따라 가장 좋은 시드만 고르지 않는다)**,
(c) 기준선 대비 최소 한 출처에서 미탐·오탐·경계 오류 중 해당 가설의 지표가 실제로 개선,
(d) 새 독립 heldout을 선택 확정 후 **한 번** 열어 같은 제약을 통과, (e) CPU 지연·메모리 보고.
(a)~(c)만 통과하면 "개발 후보"이고 채택이 아니다.

**공통 중단 규칙.**
- 개발 단계에서 통과 정책이 0이면 `no_candidate`로 기록하고 heldout을 열지 않는다(multisource-v2 선례).
- 개발 비교의 정책·cutoff·학습 설정 격자는 실행 전에 파일로 고정하고 결과를 본 뒤 추가하지 않는다.
  사전 고정 파일은 `benchmarks/results/name-p0-preregistration.json` 형태로 두는 것을 제안한다 **(가정)**.
- 개발 결과를 보고 단어·조사 예외, 이름 사전, 개별 문장 예외를 넣지 않는다.
- 추론은 순차 실행, 낮은 우선순위, CPU 제한(`nice -n 15 taskset -c ...`)으로 한다
  (4코어 WSL에서 동시 추론 중 부하가 발생한 전례).

### 2.1 P0-1 공동 문자 구간 채점 + 전역 구간 선택 (A2)

- **가설.** 문자별 argmax는 후보를 만들지 못한다(합성 미탐의 10/23은 후보 없음, 실제 문장은 토큰 내부 경계 45개).
  시작·끝·내부·문맥을 함께 채점하고 비겹침 총점 최대 조합(동적 계획법)으로 고르면 후보 누락과
  경계 오류가 줄 것이다. **공동 구간 v1이 합성 학습만으로 외부에서 실패했으므로, 이번에는 실제 문장·대화
  다출처 학습에서도 같은 구조가 실패하는지 확인하는 것이 핵심이다.**
- **변경 요인.** 구간 헤드와 선택 방식만. 인코더는 고정(`name_span_experiment.py` 구조 유지).
  통제 대조: (i) 같은 다출처 자료로 학습한 문자 BIOES 헤드(multisource-v2 head, 가중치 1),
  (ii) 같은 구간 헤드에서 전역 선택 대신 기존 병합 사용.
- **자료.** 공통 학습·검증(위). 사전 고정 구간 cutoff는 multisource-v2의 10개
  (.01, .025, .05, .1, .2, .3, .5, .7, .9, .99)를 재사용하고 인물/O 손실 가중치는 1로 둔다
  (v1 일반화의 가중치 4가 KDPII 오탐 원인 후보로 지목됨). 최대 구간 길이 L은 학습 자료에서 정하되,
  초과 정답은 버리지 않고 실패시킨다(기존 구현은 32글자).
- **측정.** 공통 지표 + 후보 상한 분해(정확 후보 존재, 임계 후 존재, 병합 후 존재 — 실제 문장 개발 자료로
  확장; `benchmarks/name_context_stage_diagnostic.py`는 합성 단일 창 전용이므로 확장 필요) +
  긴 문서 창 병합 시 잘림·중복·누락 재현 테스트(`tests/test_name_span_adapter.py` 확장).
  구간 계산이 문장 길이의 제곱에 비례하는 문제는 속도·메모리로 별도 보고.
- **재사용.** `scripts/name_span_experiment.py`, `train_name_span_experiment.py`, `name_span_adapter.py`
  (주소 공유 인코더 실행), `evaluate_name_span_public.py`, `evaluate_name_span_external.py`,
  다출처 자료 `prepare_name_multisource_data.py`·`train_name_multisource.py`,
  개발 재생·실추론 일치 `collect_name_multisource_development.py`·`evaluate_name_multisource_live.py`,
  정책 비교 `name_multisource_selection.py`, 게이트 `check_name_multisource_release.py`,
  KDPII `evaluate_name_kdpii.py`.
- **채택 게이트.** 2.0 공통. 추가로 기준선 대비 (미탐 또는 이름 전체 가림 실패)가 줄어야 한다 —
  오탐만 줄이고 미탐이 같으면(선택 필터 사례) 이득 없음.
- **중단 기준.** 3시드 모두 개발 자료 한 출처 이상에서 제약 위반이거나 기준선 대비 개선 지표가 없으면
  이 구조를 `no_candidate`로 종료하고 구간 채점기의 추가 조정은 하지 않는다. 합성 단독 대비 외부 개선이 없는데
  다출처 학습에서도 실패하면 "구조가 아니라 표현(인코더) 문제" 가설을 P0-4로 이관한다.

### 2.2 P0-2 합법 BIOES 전이 제약 (A1)

- **가설.** I/E만으로 구간이 시작되는 비합법 경로가 경계 오류의 일부다. 합법 경로 제약(Viterbi) 또는
  모든 합법 경로의 forward-backward 확률이 경계 오류를 줄인다. 기존 증거는 약하다:
  합성 검증 96문장에서 오탐 2→1, 미탐 불변(105/1/3), 주소 충돌 포함 전체 비교 아님.
  일반화 v1은 Viterbi를 쓰고도 최적 경로에 이름 후보가 없는 29건으로 전체 가림이 33개 줄었다.
  → **전이 제약은 후보 누락을 해결하지 못할 가능성이 높다 (가정이 아니라 기록된 관찰).**
- **변경 요인.** 같은 헤드·같은 캐시·같은 cutoff에서 디코더만: (D0) 비제약 argmax, (D1) 합법 BIOES Viterbi,
  (D2) 합법 경로 forward-backward 구간 존재 확률(`name_coverage_decoding.py` 재사용), (D3) D1 + 전역 비겹침 선택.
  재학습 없는 계산이므로 가장 저렴하다. P0-1과 병렬 가능하나 P0-1의 헤드 출력이 필요한 D3는 P0-1 이후.
- **자료.** 공통 학습 후 **검증 캐시**에서 먼저(96 합성만으로 판단하지 않는다), 이어서 개발 자료 전체의 캐시 재생.
- **측정.** 경계 유형별 오류(끝 글자 절단, 조사 포함 과대 구간, 옆 단어 결합), 공통 지표.
- **재사용.** `scripts/name_bioes_ablation.py`, `evaluate_name_bioes_ablation.py`,
  `name_coverage_decoding.py`, `select_name_coverage.py`, `tests/test_name_bioes_ablation.py`,
  `tests/test_name_coverage_decoding.py`.
- **채택 게이트.** 2.0 공통. 디코더만 바뀌므로 구간별 회귀가 곧바로 판별된다. 동치 대조(D0)와 D1이
  모든 출처에서 같으면 이득 없음.
- **중단 기준.** D1~D3이 개발 자료에서 경계 오류를 줄이지 못하거나 어느 출처에서든 새 노출·새 오탐이면 종료.
  전이 제약의 단독 효과가 없으면 문서에 그 사실(원인 기여도 분리 결과)을 기록하는 것으로 충분하다.

### 2.3 P0-3 문맥 대조 학습 (A5)

- **가설.** 이름 철자 편향(Name Regularity Bias)과 경계 음성 부족이 낯선 이름·문맥 오류의 원인이다.
  (i) 정답의 조사 포함·한 글자 절단·옆 단어 결합 후보를 어려운 음성으로, (ii) 같은 철자의 인물/비인물 대조 쌍으로,
  (iii) 이름만 바꾼 문장에서 판정 유지를 학습하면 경계 오류와 철자 의존 오탐이 줄 것이다.
  한국어에서의 효과는 문헌에서 검증되지 않았다 — 측정 대상이다.
- **현재 상태.** 구현 없음(알고리즘 연구는 "명시적 문맥 대조 손실 미구현"이라 기록). 새로 구현해야 한다.
- **변경 요인.** P0-1에서 선택한 구조(또는 P0-1이 `no_candidate`면 multisource-v2 문자 헤드)에 대조 자료·손실을
  넣거나 뺀 것만 비교. 시드·예산 동일.
- **자료.**
  - 경계 음성: 학습 split의 **실제 문장**(KLUE train, KDPII train)의 정답에서 기계적으로 생성 — 사전 고정한
    변형 규칙(조사 포함, 끝/앞 글자 절단, 이웃 단어 결합)을 코드로 쓰고 결과를 본 뒤 규칙을 추가하지 않는다.
  - 이름 치환: 학습 split의 이름 철자 집합 안에서만 치환. 이름 철자 분리를 유지하고, 평가 자료의 이름은 사용하지 않는다.
  - 인물/비인물 동형어 대조: 기존 합성 v4 대조 자료(`name_context_v4_cases.py`, `tests/test_name_context_v4_contrasts.py`)와
    KLUE train에서 같은 표면형이 PS와 비-PS로 모두 나타나는 문장이 충분한지는 **(가정) 확인 전에는 알 수 없다.**
    합성에만 의존하면 공동 구간 v1과 같은 편중이 재발하므로, 합성 대조는 학습 split 안에서만 쓰고
    실제 문장 파생분과 비중을 사전 고정한다. 모호한 문장의 정답을 임의로 만들지 않는다(구간 계약).
  - 같은 템플릿·같은 문서의 변형은 분할을 넘지 않는다.
- **측정.** 공통 지표 + 이름 치환 불변성(이름만 바꾼 개발 문장에서 같은 상대 구간이 유지되는 비율 — 이번 실험이
  정의하는 보조 진단이며 채택 지표가 아님) + 동형어 대조 쌍의 인물/비인물 구분.
- **재사용.** `benchmarks/name_context_v4_cases.py`·`name_context_v4_benchmark.py`(대조 틀),
  `scripts/train_name_context_v11.py`(어려운 표본 재학습 구조), 위 P0-1 도구 일체. 대조 손실은 신규.
- **채택 게이트.** 2.0 공통. 대조 자료 제외 대조군과 비교해 해당 지표(경계 오류 또는 철자 의존 오탐)가 개선되어야 한다.
  대조 자료 포함이 어느 출처에서든 기존 이름을 잃게 하면 탈락(v4의 전례: 비인물 12건 해결, 기존 이름 8개 손실).
- **중단 기준.** 포함/제외 대조에서 개발 자료의 개선이 없거나 회귀가 생기면 종료한다. 실패 문장을 추가 학습하는
  반복(PRD가 중단한 방식)으로 전환하지 않는다.

### 2.4 P0-4 인코더 적응 제거 실험 (A4)

- **가설.** 고정 E5 표현이 한국어 이름 경계·낯선 문맥에 충분하지 않다. 부분 미세조정(LoRA)이 도움이 되지만,
  일반화 v1의 LoRA는 대화 자료 없이 KLUE+합성으로만 학습되어 KDPII 오탐을 낳았으므로,
  **LoRA 자체의 효과와 학습 자료 구성의 효과가 섞여 있다.** 다출처 자료로 학습한 LoRA는
  문서에서 시도된 기록이 없다 **(가정: 문서에 없음)**.
- **변경 요인(동일 자료·예산·시드·디코더).** (E0) 인코더 고정(multisource-v2 head 구조), (E1) 마지막 4층 query/value
  rank 8 LoRA(기록된 기존 설정), (E2) **(가정, 선택)** 적응 범위 확대 한 단계(예: 층 수 또는 rank).
  이름 판정에만 적응 경로를 쓰고 기존 E5 확률·주소는 원래 모델에서 얻는 구조를 유지한다.
  P0-1·P0-2의 최선 디코더를 고정한 뒤 수행한다(요인 혼합 방지).
- **자료.** 공통 학습·검증. 이름이 드문 대화 출처의 비인물 문장을 학습·검증에 충분히 포함
  (KDPII train에서 이름 양성 378문장 vs 대부분이 무이름 문장이라는 기록을 유지).
- **측정.** 공통 지표 + CPU/CUDA 정밀도 차이: 적응 경로는 CUDA BF16, 원래 prior는 FP32이므로
  `scripts/check_name_adaptation_device_parity.py`로 구간·마스킹 차이를 보고(점수 차이 11/100문장 전례).
  학습 시간·지연은 별도 보고(정확도 평가는 지연 근거가 아님).
- **재사용.** `scripts/name_encoder_adaptation.py`, `train_name_encoder_adaptation.py`, `name_adapted_adapter.py`,
  `collect_adapted_name_development.py`, `evaluate_name_generalization.py` 계열 평가기와
  `tests/test_name_encoder_adaptation.py`, `tests/test_name_adapted_adapter.py`, `tests/test_name_adaptation_device_parity.py`.
- **채택 게이트.** 2.0 공통 + E1/E2가 E0보다 개발 자료에서 개선되고 KDPII 비인물 오탐 문장이 기준선 이하.
- **중단 기준.** E0 대비 이득이 없거나 KDPII류 출처의 오탐이 늘면 적응을 중단한다. 이 경우 구조·표현 개선이
  모두 한계라는 증거이므로 A6(외부 한국어/다국어 PII 모델 비교: K-LegalDeID의 KLUEBERT-CRF,
  GLiNER2-PII 등 — 한국어 학습 여부·라이선스·오프라인 비용 확인 후)로 넘어간다.

### 2.5 후속: 조합과 교정

P0-1~4에서 개발 후보가 남으면 가장 좋은 조합을 3시드로 다시 학습하고 개발 자료에서 게이트를 확인한다.
cutoff·교정은 **별도 calibration 분할**(3.3)에서만 정한다. 현재는 calibration 자료가 없으므로 그때까지는
개발 자료에서 사전 고정 격자만 비교하고 그 사실을 보고서에 명시한다. 보류(abstain)는 정답이나 마스킹 성공으로
집계하지 않는다. A6(외부 모델)은 P0-1~4 종료 후 필요하면 수행한다.

"출처·문서·작성 방식·분야가 분리되고 별도 검수된" 자료가 아니다.
(1) 이미 소모한 자료와 같은 출처·같은 라벨 정책·같은 원문 풀이다(기사·리뷰·대화 그룹 정보가 없어
문장 분리가 원문 독립성을 보장하지 않음).
(2) E5가 KLUE train·KDPII를 학습했다고 명시하며 test/dev 포함 여부를 독립 감사하지 못했다.
(3) 별도 검수가 없다. 따라서 예비 자료는 **보조 확인용**으로만 쓴다 — 개발 단계를 모두 통과한 최종 후보에 한해
한 번 열되, 열면 소모되고, 결과를 "독립 일반화"로 표기하지 않는다. 열기 전 정확·정규화 텍스트 중복 감사를
다시 수행한다(multisource-v2에서 KDPII 6개 ID 중복이 추론 전에 발견된 전례). 이 사용 방식 자체는 **(가정)**이다.

### 3.2 새 독립 heldout 확보 절차

1. **소모 장부 동결.** 위 표를 ID·텍스트 해시 목록과 함께 하나의 장부로 만들고 이후 모든 열람을 기록한다.
   (기존 `benchmarks/results/*-reserve.json`, `*-selection.json`, `*-amendment.json` 형식을 확장 **(가정)**.)
2. **출처 선정.** KLUE·KDPII와 출처·작성 방식이 다른 한국어 자료를 선정한다. 후보는 공개 한국어 코퍼스
   (예: 국립국어원 말뭉치, AI Hub류 — **본 계획은 가용성·약관·재배포 가능 여부를 확인하지 않았다 (가정)**)와
   PRD P1의 업무 문서(상담·계약·배송·결제)다. 알고리즘 연구의 규정대로 출처·이용 조건·라벨 정책·원문 좌표를
   검토하고 논문 접근 가능성과 재배포 허가를 구분한다. 개인정보가 담긴 실제 업무 문서는 법적·내부 검토가 선행되어야 한다.
   공개 인물 NER 라벨과 개인정보 마스킹 정책의 차이는 정책 문서로 먼저 정한다.
3. **분할.** 문서·작성자/생성기·분야 단위로 calibration과 heldout을 나누고, 같은 문서의 변형은 분할을 넘지 않는다.
   이름 철자 분리를 유지한다. 선택은 모델 출력·이름 유무·문장 길이와 무관하게 ID 해시 순위로 하고,
   **정답 주석을 파싱하기 전에** 선택 ID 목록과 해시를 고정한다(KLUE/KDPII 평가의 기존 절차).
   기존 학습·개발과 정확·정규화 텍스트 중복이 있으면 추론 전에 제외하되 대체 추출은 하지 않는다.
4. **검수.** 구간 계약 + 정책 문서를 지침으로, **서로 독립적인 두 명 이상의 사람**이 주석하고 제3자가 조정한다.
   일치도와 불일치 항목을 기록한다. 모델 예측을 미리 보여 주는 사전 주석은 쓰지 않는다 **(가정: 기준 편향 방지)**.
   경계가 확정되지 않는 문장은 별도 모호성 자료로 두고 모델 예측을 보고 정답을 바꾸지 않는다.
   외래 인명(KLUE "가르시아"류)·별명·가상/공인 인물 정책을 지침에 명시하고 정책별로 따로 보고한다.
   모델 개발자와 자료 생성자가 같은 합성 자료만으로 최종 성능을 확정하지 않는다(알고리즘 연구).
5. **규모.** **수치를 이 문서에서 정하지 않는다.** 이름이 드문 출처(KDPII 500문장에 이름 18개)가 있으므로,
   동결 기준선의 출처별 이름 비율과 부트스트랩 구간 폭으로 필요한 문장 수를 사전에 계산해 선정 전에 고정한다 **(가정)**.
   이름 양성 문장과 비인물 문장 모두 충분해야 한다. 이름 유무로 표본을 고르지는 않는다 — 부족하면 출처를 늘린다.
6. **열람 규칙.** 후보·체크포인트·cutoff·디코더를 확정하고 `finalized: true`와 파일 해시를 기록한 뒤 **한 번** 연다.
   실행 중 코드·가중치·원천이 바뀌면 결과를 승인하지 않는다. 결과를 본 뒤 같은 자료로 재선택하지 않으며,
   실패를 수정에 쓰면 해당 자료 전체를 개발로 전환한다. 열람 후 자료는 다음 독립 검증에 재사용하지 않는다.
7. **E5 노출 문제.** E5가 이미 본 자료는 독립적이라 주장하지 않는다. 새 출처가 가능하면 E5 학습 원천(KDPII, KLUE train,
   합성 문서)과 겹치지 않는 자료를 우선한다. 사전학습 노출 여부는 확인할 수 없으면 한계로 기록한다.

### 3.3 Calibration 세트

- 3.2의 같은 출처·절차로 heldout과 **분리된 문서**에서 만든다. 용도는 cutoff·점수 교정·처리 정책 선택뿐이며
  체크포인트 선택(검증분)과 구분한다. 분야 변화에서 신뢰도 순위가 바뀐다는 문헌(Reliable Financial NER)에 따라
  출처별로 교정하고, 고정 점수를 확률로 표현하지 않는다.
- 이름이 드문 출처(대화)도 포함한다. 한 출처의 낮은 cutoff 개선이 다른 출처로 일반화되지 않은 전례(일반화 v1)가 있다.
- calibration 결과로 정한 설정을 heldout에서 바꾸지 않는다. 사용 후 calibration은 개발 자료로 전환된다.

### 3.4 새 자료 전까지의 임시 규칙

- 결과는 "개발 자료 기준 후보"로만 표기한다. 단일 점수·합성 회귀 통과로 오류 0 또는 일반화를 선언하지 않는다.
- 모든 결과 JSON에 사용한 자료의 상태(학습/검증/개발/최종)를 기록한다 **(가정)**.

## 4. 일정 순서와 위험

### 4.1 마일스톤 (기간은 정하지 않는다)

| 단계 | 내용 | 선행 | 산출물 |
|---|---|---|---|
| M0 | 소모 장부 동결, 기준선 E5 재측정(개발 자료, 같은 device), 사전 등록 파일 작성. **새 heldout/calibration 출처 선정·주석 준비를 병렬 시작**(리드타임이 길다) | — | 장부, 기준선 JSON, 사전 등록 |
| M1 | 공통 다출처 학습 자료·특징 캐시 해시 고정(중복 감사) | M0 | 입력 manifest |
| M2 | P0-2 D0~D2 (재학습 없음, 가장 저렴) | M1 | 디코더 제거 보고 |
| M3 | P0-1 구간 채점 + 전역 선택, 3시드 | M1 | 개발 후보 또는 `no_candidate` |
| M4 | P0-2 D3 (P0-1 헤드 + 디코더) | M2, M3 | 조합 보고 |
| M5 | P0-3 대조 학습 구현·포함/제외 대조 | M3 (또는 M1) | 개발 후보 또는 종료 |
| M6 | P0-4 인코더 적응 E0/E1/(E2) | M4 | 적응 효과 분리 결과 |
| M7 | 최선 조합 3시드 재확인, calibration에서 cutoff 확정, 선택 manifest `finalized` | M3~M6, calibration 준비 | 확정 후보 |
| M8 | 새 독립 heldout 1회 열람 + 회귀 게이트, CPU 지연·메모리 | M7, 새 heldout | 채택/거부 기록 |
| M9 | 모든 P0가 `no_candidate`면 A6 외부 모델 비교로 이동 | M2~M6 | 비교 보고 |

### 4.2 위험과 완화

| 위험 | 근거 | 완화 |
|---|---|---|
| 독립 heldout 확보가 지연되어 모든 결과가 개발 수준에 머무름 | 현재 독립 자료 없음 | M0에서 병렬 착수. 지연 시 PRD P0를 "미해결"로 유지하고 채택 선언 금지 |
| 개발 자료 반복 사용으로 과적합 | 개발 자료가 이미 6개 규모 | 격자 사전 고정, 반복 횟수·후보 수 기록, 개발 통과를 채택으로 쓰지 않음 |
| 합성 편중 재발 | 공동 구간 v1 외부 F1 59.79~64.73% | 모든 실험에 실제 문장·대화 포함, 합성은 학습 split 한정 |
| 이름이 드문 출처의 오탐 폭증 | 일반화 v1 KDPII 오탐 2→116 | KDPII류를 출처별 게이트로 분리, 낮은 cutoff 격자는 출처별 평가 후에만 |
| 후보 누락(상한) 문제로 구조 변경 이득 없음 | 선택 필터 이득 0, 전이 제약의 미탐 불변 | 후보 상한 분해를 모든 실험에 포함 |
| 라벨 정책 불일치(공인·가상 인물, 별명, 외래 인명)가 지표를 왜곡 | KLUE PS에는 공인·가상 인물 포함, KDPII 별명 14 | 정책별 병렬 보고, 사후 주석 변경 금지 |
| 평균 F1만 보고 개별 회귀 놓침 | 일반화 v1 평균 개선·노출 12 | 구간 단위 회귀 3종 게이트 |
| 거부 후보의 수치 혼용 | 운영 승인 철회 | 같은 실행·같은 기준선만 비교, 표에 후보·기준선 동시 기재 |
| E5의 KLUE/KDPII 사전 노출 | 모델 카드 명시, 감사 불가 | 한계 상시 기재, 가능하면 새 출처 |
| 자원 부하로 실행 중단 | 4코어 WSL 부하 전례 | 순차 실행, `nice`·CPU 제한 |
| 장문에서 짧은 문장과 다른 알고리즘이 적용됨 | 긴 문서에서는 보조 판정기·필터 비활성(알고리즘 연구) | 창별 동일 판정기 + 전역 선택을 재현 테스트로 검증 |
| 기대하는 개선이 존재하지 않을 수 있음 | 오류 0은 약속 불가 (알고리즘 연구) | 모든 P0가 종료되면 결과를 그대로 기록하고 기본 런타임은 E5 유지 |

### 4.3 이 계획이 확정하지 않은 것

수치 목표, 새 heldout의 크기와 출처, 대조 학습의 자료 비율, 적응 범위 E2, 3시드 전원 통과 규칙, 사전 등록 파일 형식,
지연 측정 도구의 적합성은 모두 **(가정)** 이며 M0에서 확정한다.
