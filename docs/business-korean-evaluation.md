# 한국어 업무 문장 이름 탐지 평가

[`benchmarks/data/business_korean.jsonl`](../benchmarks/data/business_korean.jsonl)은
공문·업무 메일·입력 양식에서 사용하는 표현을 바탕으로 직접 작성한 **합성
개발 회귀 데이터**다. 실제 메일함이나 공문에서 수집한 자료가 아니다. 같은
틀의 이름만 바꾸어 분모를 늘리지 않고 서로 다른 요청·역할·자리표시자·일반명사
용법을 골랐다. 일부 짧은 기본 사례는 다른 회귀 테스트와 겹치므로, 독립적인
외부 평가 자료라는 의미의 독립성을 주장하지 않는다.

| 구분 | 문장 수 | 이름 정답 구간 수 | 내용 |
|---|---:|---:|---|
| `negative` | 62 | 0 | 업무 요청, 일반적 역할·호칭, 빈 값, 지시문, 일반명사 |
| `positive` | 20 | 21 | 명시적 인명 필드와 문장 속 합성 인물의 대조 사례 |

이 표는 데이터 구성이다. 탐지 실행 결과나 정확도 수치가 아니다. 양성 예시의
이름은 특정 실존 인물의 정보를 수집한 것이 아니지만 동명이인이 있을 수 있다.
파일명에 사람 이름이 들어 있으면 개인정보일 수 있으므로 그런 파일을 음성
사례로 사용하지 않았다. `검토요청서.pdf`처럼 인명이 없는 첨부파일만 포함한다.

## 평가 범위

이름의 정답 엔티티는 `KR_NAME`이다. 이름·주소 탐지는 사용자가 선택해서
켜는 기능이며, 이 평가에서는 이름 탐지를 **명시적으로 켠 설정**을 보고한다.
기존 식별번호 9종을 사용하는 기본 설정의 성능과 섞지 않는다. 이 데이터에는
주소 정답이 없고, 이름·주소 통합 기능 전체의 정확도를 대표하지 않는다.

업무 문장에 `담당자`, `수신자`, `발신인`, `책임자`, `참고인`, `관계자`,
`귀하`가 등장한다는 이유만으로 특정 개인의 이름이 존재한다고 보지 않는다.
반면 `수신자: 오지은`은 실제 이름값을 지정하므로 양성이다. 같은 기준으로
`성명 입력 필요`는 지시문이고 `성명: 이상`은 이름 필드다.

`이상`, `소망`, `하나` 등은 문맥에 따라 판단한다. `점검 결과 이상 없음`이나
`새해의 소망`은 일반명사이고, `신입 이상이 초안을 작성했다`와
`동료 소망에게 문서를 전달했다`는 인물이다. 따라서 일반명사를 단순히 이름
금지어로 등록해서 음성 결과만 좋아지는 변경은 양성 대조 사례에서 드러난다.

## 정답과 태그

각 줄은 다음 필드를 가진다.

- `id`: 사례를 식별하는 고유 ID
- `scope`: 이 파일에서는 `business_korean`
- `category`: `negative` 또는 `positive`
- `track`: 음성은 `business_negative`, 양성은 `structured` 또는 `free_prose`
- `tags`: 요청문, 역할 필드, 자리표시자, 일반명사 대조 등 문장의 평가 목적
- `text`: 합성 원문
- `expected`: 원문에 대한 `entity`, `start`, `end` 정답 목록

인덱스는 Python 문자열의 시작 포함·끝 제외 위치다. 이름 전체를 포함하되
라벨, 조사, `귀하` 등의 호칭은 제외한다. 이름 두 개가 있는 문장은 각각
독립된 구간을 기록한다. 정답은 모델 출력과 무관하게 작성했으며, 모델이
놓쳤다는 이유로 양성 사례를 음성으로 바꾸지 않는다.

양성의 `structured` 태그는 이름값을 가진 명시적 필드, `free_prose`는 문장
의미를 해석해야 하는 사례다. 기본 규칙과 선택 모델은 같은 입력을 평가하되
두 범주의 결과를 따로 기록한다. 선택 모델을 내려받지 않는 CI에서는 음성
회귀와 지원하기로 한 구조화 양성 계약을 검증할 수 있다. 자유 문장에 대해
실제 실행하지 않은 모델의 성능을 가정하거나 정확도 100%를 요구하지 않는다.

## 보고 방법

음성은 **오탐 문장 수 / 62문장**을 먼저 보고한다. 한 문장에서 여러 오탐이
나올 수 있으므로 탐지 구간 수는 별도 수치로 기록한다. 양성은 정확한 엔티티와
구간이 모두 일치하는 재현율, 전체 정답 구간이 실제 마스킹되는 비율을 함께
본다. 전체 exact-span precision·recall·F1은 양성·음성을 모두 평가했을 때만
계산하고, `structured`·`free_prose` 분리 결과를 유지한다.

실행 보고서에는 활성화한 엔티티, 기본 규칙 또는 모델 설정, 임계값, 선택
모델의 저장소·고정 revision, 데이터 SHA-256, 실행 명령을 남긴다. 실패한
사례의 ID와 예측 구간도 보존한다. 이 파일로 규칙을 개발한 뒤 얻은 결과는
개발 회귀 수치이며, 독립적인 실사용 성능 추정치는 아니다. 별도로 수집·승인한
도메인과 작성자의 문장을 분리해서 평가하기 전에는 현업 전체에 대한 오탐률로
일반화하지 않는다.
