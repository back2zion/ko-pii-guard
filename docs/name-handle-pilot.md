# 별명·계정 핸들 자료 조사와 검수 파일럿 (개발 단계, 학습 전)

후보 B(단순 범위 확장)는 `docs/name-p0-gpu-ab.md`의 기준으로 **미채택 종결**이다. 별명·핸들 보호는 필수 범위이며
상태는 "현재 구현 미충족"이다. 이 문서는 후속 학습을 정하기 전의 자료 조사 결과이며 학습·제품 변경·예비셋 개봉은 없다.

## 1. 허용된 기존 자료의 별명·핸들 분포 (KDPII v1 공식 train/valid, 체크섬 확인)
`scripts/survey_name_nickname_pool.py` (집계만 저장: `benchmarks/results/name-kdpii-nickname-pool-survey.json`).

| 항목 | train (40,109문장) | valid (5,011문장) |
|---|---|---|
| PS_NICKNAME 개체 / 문장 | 1,057 / 1,031 | 152 / 150 |
| PS_NICKNAME 고유 문자열 | 773 | 131 (train과 공유 26) |
| PS_NICKNAME 포함 ID 접두 묶음 | 706 | 105 |
| PS_ID(계정 핸들) 개체 / 고유 문자열 | 483 / 379 | 60 / 53 |
| PS_NAME 개체 | 1,555 | 179 |
| 닉네임이 있으나 실명은 없는 문장 | 1,008 | 146 |
| 평가용 텍스트와 동일해 제외 | 245 | 20 |

- 이전 학습(`prepare_name_multisource_data.py`)은 PS_NICKNAME·PS_ID를 `training_ignore_spans`로 두어 양성도 음성도
  아닌 무시 구간으로 처리했다. 별명·핸들은 학습 신호로 쓰인 적이 없다.
- 평가 슬라이스(500·1992)와 예비 자료는 이 풀에 넣지 않았다. 개정 통합본(KDPII REVISED)은 사용하지 않았다.
- 접두 묶음(`ID`의 첫 `_` 앞)이 원대화 ID인지는 **아직 확인하지 못했다(가정)**. 새 분할에는 검증된 식별자가 필요하다.
- E5가 KDPII·KLUE 학습 원천을 포함하므로 train/valid 행이 기초 체크포인트에 대해 미사용이라고 보장하지 않는다(미확인).

## 2. 검수 파일럿 400문서 (`benchmarks/data/name_handle_pilot_v1.jsonl`)
`scripts/build_name_handle_pilot.py`로 생성, 매니페스트 `name_handle_pilot_v1.manifest.json`. 출처: KDPII v1 train
(CC-BY-4.0), 선택은 ID 해시 순위, 접두 묶음당 1문장, 한 문장에 대상 구간 1개, 평가 동일 텍스트 제외.

| 층 | 문장 | 출처 라벨 → 초기 역할 |
|---|---|---|
| nickname | 140 | PS_NICKNAME → 개인 지칭 후보 |
| account_id | 60 | PS_ID → 개인 지칭 후보(계정 핸들) |
| club_group_name | 120 | OGG_CLUB → 비개인 후보(별명처럼 보이는 동아리·모임명) |
| workplace_name | 40 | OG_WORKPLACE → 비개인 후보 |
| school_name | 40 | OGG_EDUCATION → 비개인 후보 |

400개 고유 접두 묶음, 391개 고유 대상 문자열. 부족분 0. **모든 `policy_label`은 `unreviewed`**이며 출처 라벨은 그대로 보존한다.

### 검수 절차 v2: 에이전트 2개의 블라인드 판정 + 곽두일의 조정·표본 감사
"사람 2인 독립 검수"가 아니다. 역할: 에이전트 A·B가 각각 새 컨텍스트에서 400문서를 판정하고, 곽두일이 불일치·불충분·
정책 미정 사례를 조정하며 일치 사례의 10%를 표본 감사하고 최종 승인한다.
1. A·B는 고정 지침(`docs/name-handle-review-guideline-v1.md`), 익명 ID(`r001…`, 시드 20261030으로 섞음), 원문, 대상 구간만 받는다.
   KDPII 원래 라벨, 층 이름, 양성·음성 구성, E5 예측, 후보 B 성능, 서로의 판정은 숨긴다. 열람 가능 파일은 입력 2개로 제한하고
   실행 뒤 도구 호출 기록으로 준수 여부를 감사한다. 에이전트 대화 이력은 이어받지 않는다.
2. 판정 `personal / non_personal / insufficient` + 대상 구간 확인(`span_ok`) + 문장에서 인용한 근거 + 적용 정책 항목(P1~P7).
   `policy_pending`은 내용 판정과 별개 상태이며, 지침이 정하지 않은 정책 질문에 판정이 달린 경우에만 표시하고 질문을 적는다.
   정책이 정해졌지만 문맥이 부족하면 `insufficient`다.
3. 조정 대상은 전부 곽두일에게 올린다: A·B 불일치, 어느 한쪽이라도 `insufficient`, `policy_pending`. 문맥에 답이 없으면 억지로
   양성·음성을 확정하지 않는다. 정책이 확정되면 영향받는 모든 사례를 같은 지침으로 재판정한다(불일치 사례만 고치지 않는다).
4. 일치한 사례는 판정별로 층화해 10%를 고정 난수로 뽑아 곽두일이 확인한다. 10%는 감사 작업량이며 정답 품질을 보증하는 통계 기준이 아니다.
   에이전트 간 일치가 정답의 증명도 아니다.
5. 상태 기록: `agent_consensus`(에이전트끼리만 일치), `human_adjudicated`(곽두일 조정), `human_audited`(일치 판정을 곽두일이 표본 확인).
   A·B의 최초 판정은 조정 결과로 덮어쓰지 않고 보존한다. 파일럿 최종 승인은 400문서 전부를 사람이 직접 검수했다는 뜻이 아니다.
6. 원자료 200:200 구성은 최종 정책 정답 비율과 무관하다. 모델 ID·버전, 프롬프트·지침 해시, 실행 설정을 기록한다.
   (A와 B는 서로 다른 모델 계열로 실행해 오류 상관을 줄이려 했으며, 같은 계열이 아니라는 점이 독립성을 보장하지는 않는다.)
7. 이 400문장은 개발·검수 자료이며 최종 평가가 아니다. 기존 평가 슬라이스와 짝지은 문맥 192건은 개발·회귀 자산으로 유지하며 학습에 쓰지 않는다.

### 어시스턴트 예비 점검 (독립 사람 검수가 아님)
30문장을 훑었다. 개인/비개인 구분은 대체로 출처 라벨과 맞았으나 **정책 애매 항목**이 보였다: 애정 호칭("애기", "공주님"처럼
일반어를 개인에게 부르는 말), 문맥이 짧아 개인 계정과 공용 계정을 가르기 어려운 핸들, 동아리명이 인명과 같은 문자열("연화").
이 비율은 표본이 작아 추정값이 아니다. 별명 정책(일반어 호칭을 보호할지 포함)을 검수 지침에 먼저 명시해야 한다.

## 3. 저장된 예측으로 본 오류 원인 (`name-p0-handle-candidate-diagnosis.json`)
후보 B의 출력은 임계값 0.9 이상만 저장돼 있어 "후보 없음"과 "임계값 아래"를 구분할 수 없다(임계값은 탐색하지 않았다).

| 자료 | 별명 정답(실명 제외) | B 출력에 정확히 있음 | 겹치지만 경계 다름 | 출력 없음/임계값 아래 | B의 틀린 구간 중 정답과 겹치지 않음 |
|---|---|---|---|---|---|
| KDPII 500 | 14 | 12 | 1 | 1 | 10 / 12 |
| KDPII 1992 | 34 | 31 | 2 | 1 | 40 / 47 |

고정 후보 집합이 별명 정답을 담는 비율은 정확 일치 기준 86%·91%, 겹침 기준 93%·97%다(표본이 작다).
따라서 후보 선택(개인 지칭 문맥 판정)이 주된 문제로 보이며 후보 생성은 부차적이다. 단, 이 결론은 이미 정답을 연 두 슬라이스의
적은 개수에 근거한다. 통과·제외만 하는 필터는 후보 집합 밖의 정답을 만들 수 없으므로 재현율 상한은 위 비율이다.

## 4. 단일 학습 가설과 사전 등록 초안
`benchmarks/results/name-p0-preregistration-amendment-3-draft.json` (초안, 구속력 없음): 기존 실명 출력을 유지하고,
`personal_handle` 후보 중 개인 지칭 문맥 판정을 통과한 구간만 더한다. 가설일 뿐이며 효과 보장이나 학습 착수 승인이 아니다.
검수 결과 확정과 선택식 승인 전에는 학습을 시작하지 않는다.

  계정 핸들 60 중 큐 16·일치 personal 44, 동아리·모임명 120 중 큐 8·일치 non_personal 112, 직장명 40 중 큐 2, 학교명 40 모두 일치 non_personal.
  닉네임 층의 28%가 큐로 간 것은 정책 미정 문제(아래)가 닉네임 층에 몰려 있다는 뜻이다. 이 집계는 정답 라벨이 아니다.
- 상태: 335 `agent_consensus`(그중 34건은 감사 대기), 65 `needs_adjudication`. 곽두일 조정·감사 전에는 정답이 확정되지 않았다.
- 한계: 에이전트 A는 판정을 번호 집합으로 정리해 스크립트로 기록했고 집합에 없는 항목은 기본값 non_personal/P4다. A의 `evidence`는
  구간 주변을 기계적으로 자른 문자열이다. B는 항목별 근거를 직접 썼다. 두 에이전트는 허용된 입력 파일 외에는 열지 않았음을 도구 호출 기록으로 확인했다.

### 곽두일 결정 요청: 정책 미정 질문 (에이전트가 올린 질문의 묶음)
1. 일반어를 애정 표현으로 사람에게 부르는 호칭("애기", "공주님", "마님" 등) — 보호할 것인가.
2. 자녀 이름 + 친족어 형태("OO 엄마": 테크노니미) — 개인 지칭 별칭으로 볼 것인가.
3. 태명(아직 태어나지 않은 아이를 부르는 이름) — 개인 별명으로 볼 것인가.
4. 외모 묘사·비하어를 특정인 별칭처럼 쓰는 경우("조각", "띨빵" 등).
5. 계정 핸들이 개인 계정인지 공용인지 문장에서 알 수 없는 경우(`insufficient`): 별도 집계 유지로 정리했으며 제거하거나 음성으로 바꾸지 않는다.
정책이 정해지면 **영향받는 모든 사례를 같은 지침(v2)으로 재판정**한다. 불일치했던 사례만 고치지 않는다.
