# 별명·계정 핸들 자료 조사와 검수 파일럿 (개발 단계, 학습 전)

후보 B(단순 범위 확장)는 `docs/name-p0-gpu-ab.md`의 기준으로 **미채택 종결**이다. 별명·핸들 보호는 필수 범위이며
상태는 "현재 구현 미충족"이다. 이 문서는 후속 학습을 정하기 전의 자료 조사 결과이며 학습·제품 변경·예비셋 개봉은 없다.

## 1. 허용된 기존 자료의 별명·핸들 분포 (KDPII v1 공식 train/valid, 체크섬 확인)
`scripts/survey_name_nickname_pool.py` (집계만 저장: `benchmarks/results/name-kdpii-nickname-pool-survey.json`).

| 항목 | train (40,109문장) | valid (5,011문장) |
|---|---|---|
| PS_NICKNAME 개체 / 문장 | 1,057 / 1,031 | 152 / 150 |
| PS_NICKNAME 고유 문자열 | 773 | 131 (train과 공유 26) |
| PS_NICKNAME 포함 ID 접두 묶음 | 706 | 105 |
| PS_ID(계정 핸들) 개체 / 고유 문자열 | 483 / 379 | 60 / 53 |
| PS_NAME 개체 | 1,555 | 179 |
| 닉네임이 있으나 실명은 없는 문장 | 1,008 | 146 |
| 평가용 텍스트와 동일해 제외 | 245 | 20 |

- 이전 학습(`prepare_name_multisource_data.py`)은 PS_NICKNAME·PS_ID를 `training_ignore_spans`로 두어 양성도 음성도
  아닌 무시 구간으로 처리했다. 별명·핸들은 학습 신호로 쓰인 적이 없다.
- 평가 슬라이스(500·1992)와 예비 자료는 이 풀에 넣지 않았다. 개정 통합본(KDPII REVISED)은 사용하지 않았다.
- 접두 묶음(`ID`의 첫 `_` 앞)이 원대화 ID인지는 **아직 확인하지 못했다(가정)**. 새 분할에는 검증된 식별자가 필요하다.
- E5가 KDPII·KLUE 학습 원천을 포함하므로 train/valid 행이 기초 체크포인트에 대해 미사용이라고 보장하지 않는다(미확인).

## 2. 검수 파일럿 400문서 (`benchmarks/data/name_handle_pilot_v1.jsonl`)
`scripts/build_name_handle_pilot.py`로 생성, 매니페스트 `name_handle_pilot_v1.manifest.json`. 출처: KDPII v1 train
(CC-BY-4.0), 선택은 ID 해시 순위, 접두 묶음당 1문장, 한 문장에 대상 구간 1개, 평가 동일 텍스트 제외.

| 층 | 문장 | 출처 라벨 → 초기 역할 |
|---|---|---|
| nickname | 140 | PS_NICKNAME → 개인 지칭 후보 |
| account_id | 60 | PS_ID → 개인 지칭 후보(계정 핸들) |
| club_group_name | 120 | OGG_CLUB → 비개인 후보(별명처럼 보이는 동아리·모임명) |
| workplace_name | 40 | OG_WORKPLACE → 비개인 후보 |
| school_name | 40 | OGG_EDUCATION → 비개인 후보 |

400개 고유 접두 묶음, 391개 고유 대상 문자열. 부족분 0. **모든 `policy_label`은 `unreviewed`**이며 출처 라벨은 그대로 보존한다.

### 검수 절차 (사람이 수행, 아직 수행하지 않음)
1. 검수자는 서로 독립인 2명 이상, 조정자 1명. 모델 예측·출처 라벨·층 이름을 보여주지 않는다(문장과 대상 구간만).
2. 판정: `personal`(개인을 지칭하는 별명·활동명·계정 핸들) / `non_personal`(프로젝트·서비스·팀·조직 공용 계정 등) /
   `insufficient`(원문만으로 개인 계정인지 공용인지 결정 불가; 필요한 추가 문맥을 `rationale`에 기록).
3. `insufficient`는 음성으로 바꾸거나 제외하지 않고 별도 집계한다. 처리 정책은 후속 실험 전에 정한다.
4. 일치도와 불일치 항목을 기록하고, 제품 정책 판정은 `policy_label`에, 원래 라벨은 `target.source_label`에 따로 둔다.
5. 이 400문장은 개발·검수 자료이며 최종 평가가 아니다. 기존 평가 슬라이스와 짝지은 문맥 192건은 개발·회귀 자산으로 유지하며 학습에 쓰지 않는다.

### 어시스턴트 예비 점검 (독립 사람 검수가 아님)
30문장을 훑었다. 개인/비개인 구분은 대체로 출처 라벨과 맞았으나 **정책 애매 항목**이 보였다: 애정 호칭("애기", "공주님"처럼
일반어를 개인에게 부르는 말), 문맥이 짧아 개인 계정과 공용 계정을 가르기 어려운 핸들, 동아리명이 인명과 같은 문자열("연화").
이 비율은 표본이 작아 추정값이 아니다. 별명 정책(일반어 호칭을 보호할지 포함)을 검수 지침에 먼저 명시해야 한다.

## 3. 저장된 예측으로 본 오류 원인 (`name-p0-handle-candidate-diagnosis.json`)
후보 B의 출력은 임계값 0.9 이상만 저장돼 있어 "후보 없음"과 "임계값 아래"를 구분할 수 없다(임계값은 탐색하지 않았다).

| 자료 | 별명 정답(실명 제외) | B 출력에 정확히 있음 | 겹치지만 경계 다름 | 출력 없음/임계값 아래 | B의 틀린 구간 중 정답과 겹치지 않음 |
|---|---|---|---|---|---|
| KDPII 500 | 14 | 12 | 1 | 1 | 10 / 12 |
| KDPII 1992 | 34 | 31 | 2 | 1 | 40 / 47 |

고정 후보 집합이 별명 정답을 담는 비율은 정확 일치 기준 86%·91%, 겹침 기준 93%·97%다(표본이 작다).
따라서 후보 선택(개인 지칭 문맥 판정)이 주된 문제로 보이며 후보 생성은 부차적이다. 단, 이 결론은 이미 정답을 연 두 슬라이스의
적은 개수에 근거한다. 통과·제외만 하는 필터는 후보 집합 밖의 정답을 만들 수 없으므로 재현율 상한은 위 비율이다.
