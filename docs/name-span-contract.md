# KR_NAME 구간 계약

`KR_NAME`은 문맥에서 사람을 가리키는 **이름 본체 전체**를 대상으로 한다. 이름·주소는
개발 중인 선택 기능이며, 기본 `DEFAULT_ENTITIES`에는 포함되지 않는다. 이 문서는 어떤
코퍼스의 관례를 그대로 따르는 대신, API 소비자와 평가자가 공유할 구간 규약을 정한다.

## 정답 구간의 의미

성과 이름, 복성, 라틴 문자 이름의 내부 공백은 이름에 속한다. 필드 라벨, 이름 앞뒤의
구분 공백, 실제 조사·호칭·직함·서술어는 제외한다. 이름에 원래 속한 `은`, `이`, `하나`
같은 글자는 지우지 않는다. 문맥만으로 이름의 경계를 확정할 수 없는 문장은 별도 모호성
자료에 두며, 모델 예측을 보고 정답을 짧게 바꾸지 않는다.

아래 예시는 해당 인물의 이름을 명시한 합성 주석 계약이다.

| 문장 | 이 문장에서 정한 이름 | KR_NAME 정답 | tag 마스킹 |
|---|---|---|---|
| 동료 이상은의 의견입니다. | 이상은 | `이상은` | 동료 `<KR_NAME>`의 의견입니다. |
| 동료 이상의 의견입니다. | 이상 | `이상` | 동료 `<KR_NAME>`의 의견입니다. |
| 동료 오지은은 참석했습니다. | 오지은 | `오지은` | 동료 `<KR_NAME>`은 참석했습니다. |
| 동료 김하나가 발표했습니다. | 김하나 | `김하나` | 동료 `<KR_NAME>`가 발표했습니다. |
| 동료 박이는 참석했습니다. | 박이 | `박이` | 동료 `<KR_NAME>`는 참석했습니다. |
| 성명: 김민수 님 | 김민수 | `김민수` | 성명: `<KR_NAME>` 님 |

`이상은`만 떼어 놓으면 이름 `이상은`과 이름 `이상`+조사 `은`이 모두 가능하다.
문장이나 별도의 신원 정보 없이 철자만으로 둘을 항상 구분할 수 있다고 주장하지 않는다.
`점검 결과 이상 없음`의 `이상`은 인명으로 주석하지 않는다.

## API가 보존하는 좌표

- `Finding.start`는 시작 포함, `Finding.end`는 끝 제외인 **원문 Python `str` 인덱스**다.
  UTF-8 바이트, JavaScript UTF-16 코드 단위, 화면의 글자 덩어리 위치가 아니다.
- 항상 `finding.text == original[finding.start:finding.end]`이다. 전각 문자나 일부 ASCII
  식별자 내부 제로폭 문자 정규화를 거쳐도 반환 위치와 마스킹은 원문에 대응한다.
  한글 내부 제로폭 문자를 모두 제거하는 정규화는 아니다.
- `tag`는 탐지 구간을 `<KR_NAME>`으로 바꾼다. `stars`는 탐지 구간의 모든 문자를 별표로
  바꾼다. `partial`은 `str.isalnum()`이 참인 첫 문자 하나를 남기고 이후 영숫자 문자만
  별표로 바꾼다. 공백·하이픈·결합 악센트 등 그 밖의 문자는 보존한다.
  `partial`은 이름 전체를 숨기는 방식이 아니다.
- `should_mask`로 특정 탐지 구간의 치환을 생략해도 `analyze`의 탐지 결과는 지워지지 않는다.
  파일명 속 이름에도 같은 원칙을 적용한다.

## 의미 규약과 탐지 오류의 구분

위 이름 경계는 **맞아야 할 정답**이다. 공개 모델이 항상 이 경계를 맞힌다는 보장은 아니다.
모델이 `이상은` 중 `이상`만 반환하면 끝 글자 누락이고, `이상은의`를 반환하면 조사까지
포함한 과대 구간이다. 둘 다 exact-span 오류로 기록한다. 후자는 이름을 전부 가릴 수
있으므로 실제 전체 마스킹 여부도 별도로 기록한다.

모델 후보 끝의 조사처럼 보이는 글자를 일괄 제거하는 후처리는 사용하지 않는다. 현재
명시적 이름 필드 규칙에는 붙은 `씨`·`님` 등의 호칭 처리와 모델보다 필드 구간을 우선하는
동작이 있다. 따라서 모든 경로가 후보를 그대로 반환한다거나 모든 접미부가 항상 정확히
분리된다는 뜻은 아니다. 이름 자체와 호칭이 모호한 사례도 같은 규약으로 오류를 측정한다.

[`tests/test_name_span_contract.py`](../tests/test_name_span_contract.py)는 정답 구간을
주입한 백엔드로 원문 좌표와 마스킹 동작을 검증한다. 이 테스트 통과는 학습 모델의
인식 정확도가 아니다. 실제 모델의 경계 처리는 [문맥 대조 평가](name-context-evaluation.md)의
동결된 정답과 비교한다.
