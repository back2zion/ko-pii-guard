# 실무 적용 전 확인할 근거

이 문서는 코드가 동작하는지와 업무 원문에서 충분히 정확한지를 구분한다. 공개
합성 자료의 점수나 통과한 테스트만으로 실무 원문의 안전한 비식별화를 보증할 수
없다. 현재 저장소에는 별도 주석이 완료된 업무 원문 최종 평가가 없으므로, 그
정확도에 대한 승인 판단은 보류한다.

## 현재 확인된 범위

- Python 3.10~3.13에서 테스트를 실행했고, 별도 Python 3.14 환경에서도
  기본 테스트 1,053개가 통과했다(선택 기능 585개 건너뜀). Python 3.12와
  3.14에서 실제 E5와 V11 이름 문맥 모델을 모두 켠 전체 테스트는 각각
  1,904개가 통과했다. 다만 잠금 버전 `guardrails-ai` 0.11.0은 메타데이터에서
  Python `<3.14`를 요구한다. Python 3.14의 핵심 패키지와 NER 전용 설치는
  의존성 호환성 검사와 모델 로딩을 통과했지만, Guardrails 연동의 공식
  설치 범위는 3.10~3.13으로 본다.
  CI의 이름 문맥 모델 V2·V3·V6·V7·V9·V11 수용 계약
  10개와 E5 이름·주소 회귀 검사 2개도 최종 소스에서 통과했다. 각 모델 계약은
  실행 중 소스·입력·체크포인트 변경이 없었다. 이는 기능·회귀 검증이며
  실무 원문의 정확도 추정치는 아니다.
- 공개 K-PII Bench, KDPII와 Kiii² 자료는 [공개 평가](evaluation.md),
  [문장형 평가](kiii-evaluation.md)와
  [구조화 필드 평가](structured-evaluation.md)로 분리했다. Kiii²의 개발용
  문서와 별도 예약 문서는 해시로 분리했다. 소스를 고정한 뒤 예약 문서를
  한 번 평가했으며, 문장형 탐지 개선은 없었다. 예약 결과를 규칙 조정에
  다시 사용하지 않는다.
- 구조화 JSON/JSONL/CSV의 파일 출력은 입력 검증이 끝난 뒤 원자적으로
  교체한다. 오류가 난 경우 완성되지 않은 결과를 표준 출력으로 흘리지 않는다.
  POSIX에서 파일 출력 중 `SIGINT`·`SIGTERM`을 받으면 0600 임시 파일을
  삭제하고 기존 출력 파일을 보존하는 동작도 확인했다.
- 처리 속도는 합성 입력과 특정 로컬 환경에서 별도 측정한다. 속도 수치를
  정확도 분자·분모에 섞지 않는다.
- 최종 패키지 소스 해시 `39eb4e11…`에서 [합성 불변식 검사](../benchmarks/results/final-source-invariants-2026-10-14.json)를
  다시 실행했다. 문자 50만 건의 탐지 좌표 345,171개와 기본·엄격 중첩 JSON
  각각 10만 건에서 구조·가림·입력 비변형 조건을 통과했다. 이 수치는 탐지
  정확도가 아니다.

현재 소스의 예약 Kiii² 합성 문장형 표본은 정확 구간 F1 **77.05%**이고
60문서 중 47문서에 미가림 정답이 남았다. 유형 필드형은 기본 모드에서
2,439/3,020필드를 완전히 가렸고 엄격 모드는 3,020/3,020을 가렸지만,
유형 없는 어려운 음성 필드 209개 중 37개는 양쪽 모두 바꿨다. 엄격 모드의
유형 필드 상태값 과잉 가림은 이 표본에서 측정되지 않았다. 공개 KDPII 전체
대화체에서는 이름만 선택한 기본 규칙의 F1이 **0%**, E5 NER을 명시적으로
켠 경우 **86.88%**였으며, 두 설정 모두 이전 기준 대비 개선은 없었다.
이 근거와 미완료 업무 원문 최종 평가를 고려하면 실무 자동 비식별화의
배포 승인 판단은 계속 보류한다.

## 업무 최종 평가에 필요한 입력

1. 실제 입력 경로별로 문서와 JSON/CSV 레코드를 모으고, 양성·음성·형식이
   헷갈리는 사례를 포함한다. 공개 합성 예시를 업무 자료로 간주하지 않는다.
2. 두 검토자가 가려야 하는 범위를 독립 주석하고 불일치를 합의한다. 정답에
   선택한 유형이 빠져 있으면 오탐·누락률을 해석할 수 없다.
3. 고객·문서·반복 템플릿 단위로 개발용과 최종 평가용을 분리한다. 제공된
   중복 검사는 동일 ID·동일 문서만 자동으로 찾으므로 이 분리는 사람이 확인한다.
4. [문장형 로컬 평가](private-evaluation.md)에서 유형·경계가 모두 맞는 탐지율,
   실제 별표 가림률, 정답이 있는 문서의 누락 수와 정답이 없는 문서의 오탐 수를
   확인한다. [구조화 로컬 평가](structured-evaluation.md)에서는 필드 전체
   가림·유형·음성 필드 변경을 별도로 확인한다.
5. `--strict-fields`를 쓰려면 `없음`, `미입력`, 자리표시자 같은 실제 음성
   필드도 `negative_paths`로 주석해 기본 모드와 같은 소스에서 비교한다.
   스키마가 실제로 정확한지도 확인한다.

이 자료는 사용자가 요청한 Downloads 평가 폴더의 템플릿과 실행 스크립트로
로컬에서 준비할 수 있다. 원문이나 문서 ID는 Git 저장소에 추가하지 않는다.
결과의 허용 기준은 실제 누락 비용과 과잉 가림 비용에 맞춰 평가 **전에**
정해야 한다. 최종 평가 자료를 보고 규칙을 바꾸면 그 자료는 개발용이 되어
새 최종 평가 자료가 필요하다.

서울대 [Thunder-DeID 데이터셋 소개](https://champ.snu.ac.kr/datasets-deid)의
판결문 자료도 검토했다. 공개 설명에 따르면 판결문의 대상 개체는 유형별
자리표시자로 바뀌어 있으며, 현재 환경에서는 연결된 데이터셋에 인증 없이
접근할 수 없었다. 따라서 이를 업무 원문 정확도의 근거로 사용하지 않았다.
