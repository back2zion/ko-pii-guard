## GPU 기준선
조건: float32, autocast 끔, TF32 끔, 동일 E5 revision `a308c54b`, 임계값 0.9, 창 512·stride 64, batch 4,
RTX 3090, torch 2.14.1+cu130 (`/home/woodcross/.venvs/ko-pii-gpu`). 6개 자료 모두에서 GPU와 CPU의
`analyze` 예측이 **문장 단위로 완전히 같았다**(차이 문장 0). CPU 기준선은 그대로 보존하며 GPU 기준선은 별도 기록이다.
수치는 CPU 기준선(`docs/name-p0-baseline.md`)과 같다.

B가 비개인 문맥에서 새로 표시한 것은 **65건**이다.

## 사전 등록 기준 판정
| 기준 | 결과 |
|---|---|
| 두 KDPII 별명 포함 자료에서 ΔF1 하한 > 0 | **실패** (-0.005, -0.043) |
| 잃은 정확 구간 0 | 통과 (0) |
| 실명 정답 기준 새 오탐 구간 개별 보고 | 22건, 70건 — 실명 F1이 크게 하락 |
| 비개인 문맥에서 B가 새로 표시한 건수 0 | **실패** (65) |

해석 구분: 관측 F1은 목표 정책에서 올랐지만 등록한 개선(신뢰구간 하한 > 0)·회귀(비개인 문맥) 기준을 통과하지 못했다.
"효과 없음"으로 확정한 것이 아니다. 실명 정답만 둔 평가의 "새 오탐"은 정책 불일치를 포함한다(올바른 별명도 실명 정답 대비
오탐으로 집계됨). 따라서 실명 보존은 "잃은 정확 구간 0"으로, 별명 포함 효과는 같은 실명+별명 정답에 대한 A/B로, 비개인
오표시는 짝지은 문맥으로 따로 읽는다. 아래 판정은 비개인 문맥 65건 신규 표시만으로도 성립한다.

판정: **출력 범주를 넓히는 것만으로는 별명 보호 요구를 충족하지 못한다.** 기존 `personal_handle` 출력은
개인 지칭과 비개인 지칭(문맥)을 구분하지 못하며(개인 94/96, 비개인 76/96), 실명 오탐을 크게 늘린다. 별명 재현율은 오르지만
(KDPII 500 FN 17→5, 1992 FN 47→17) 오탐이 그보다 크게 늘어 F1 개선은 신뢰구간에서 0과 구분되지 않는다.
요구 범위는 줄이지 않으며 "별명 보호 요구 미충족"으로 기록한다. 잔여 미탐(5건, 17건)과 B 외 원인(경계·임계값)은
이 대조에서 분리되지 않았다. 제품 반영·`KR_NAME` 합병은 하지 않았다. 다음 후보는 문맥 판별(개인 지칭 vs 비개인)을
학습하는 방식이어야 하며, 이는 체크포인트 선택식 확정(보완 2에서 소스 확인 완료, 트레이너별 격자는 미등록) 후 별도 사전 등록이 필요하다.
